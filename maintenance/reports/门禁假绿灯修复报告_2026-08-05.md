# 统一门禁「假绿灯」修复报告

## 一、问题：绿灯是范围太小骗出来的

统一门禁长期报「PASS ✅ 全部通过」。真相是它只把 4 个目录当核心区：

```
CORE_DIRS = ("schema", "knowledge", "projects", "methods")
```

于是这些地方的错误全被降级成「外部资料警告」，永远不阻断：

- 根目录 `README.md` / `CLAUDE.md`
- `ai/`、`goals/`、`maintenance/`
- `tools/` 导航层、推荐层、检索层

外部警告里那 4205 条噪音，绝大多数来自 `tools/cards/` 的 3572 张工具卡，
把真问题彻底淹没了。而所谓「外部资料的断链」里，**第 11 章错误链接、
AI 入口断链、维护入口断链根本不是外部资料**，是核心内容的真实损坏。

更隐蔽的第二个洞在 frontmatter 校验里：

```python
fm = parse_frontmatter(text)
if fm is None:
    continue          # 整份文件没有 frontmatter → 直接跳过，不报错
```

**越糟糕的文件越不被检查。**

第三个洞是范围定义分散在三个脚本里，各写一份且互不相同：

| 脚本 | 原 CORE_DIRS |
|---|---|
| `run_all.py` | schema / knowledge / projects / methods |
| `链接检查器-修复版.py` | schema / knowledge / projects / methods |
| `提交前校验.py` | projects / methods / schema / maintenance |

## 二、修复

### 1. 范围收敛到唯一权威定义

新增 `tools/scripts/gate_scope.py`，三分区模型，三个门禁脚本全部改为引用它，
且**不提供本地回退**——找不到该模块就直接抛错，宁可红也不假绿。

**严格区（ERROR 即 FAIL）**

- `README.md`、`CLAUDE.md`
- `ai/`、`schema/`、`knowledge/`、`projects/`、`goals/`
- `methods/`（`templates/` 与 `项目骨架模板/` 豁免占位符）
- `maintenance/`
- `tools/*.md`（导航层）、`tools/分类导航/`、`tools/推荐层/`、`tools/检索层/`

**排除区（完全不扫描）**

- `archive/`、`references/原始来源包/`、`tools/cards/`
- `maintenance/reports/history/`、`drafts/`
- 基础设施目录（`.git`、`__pycache__` 等）

**外部区（仅警告）**：其余内容，如 `references/`（除原始来源包）、
`tools/scripts/`、`tools/reports/`。

排除采用**路径前缀**匹配而非路径组件匹配，避免误伤
`projects/<书名>/drafts/` 这类项目内同名子目录。

### 2. 堵掉 frontmatter 静默跳过

严格区内缺 frontmatter 直接判 ERROR，不再 `continue`。

### 3. 报告自证覆盖范围

门禁输出现在必须打印严格区/外部区/合计的文件数与范围定义。
一个 PASS 到底是真通过还是范围太小，看报告就能判断。

### 4. 链接分类器补元变量识别

`YYYY` / `NNN` / `书名` / `路径` / `文本` 这类模板形式参数不再当成真实文件解析
（如 `goals/yearly/TEMPLATE.md` 里的 `../monthly/YYYY-01.md`）。
这是**链接分类**的修正，不是范围豁免——不会让任何目录逃出严格区。

### 5. 防回归测试

新增 `tools/scripts/validation/test_gate_scope.py`，34 条分区断言 + 两条反向断言：

- 严格区目录清单不得缺项
- 排除区不得超出约定的五项（防止有人靠加排除项来「变绿」）

范围被悄悄缩小时，表面仍是绿的、不会自己暴露，所以必须有测试钉死。

### 三条已确认的真实损坏

1. **README 第 11 章链接错误**：README 三处指向
   `第011章-初入投资圈.md`（`[历史路径]`），实际文件是 `第011章-注册公司.md`。
   README 与正文不同步，此前被当成「外部警告」忽略。
2. **AI 入口断链**：`ai/入口.md` 链 `新手入门.md`，该文件在
   `maintenance/` 下，相对路径写错。
3. **维护入口断链**：`maintenance/入口.md` 链
   `Git仓库整理项目完成通知.md`，文件不存在。

### 主要断链成因

- `tools/推荐层/` 与 `tools/检索层/` 内部用了
  `检索层/README.md` 这种缺 `../` 的相对路径
- `tools/最终索引.md` 等链向 `cards/00001__lizadaly__windrift.md`，
  但工具卡编号实际从 `00002` 开始，`00001` 不存在
- `tools/检索层/按评级/` 只有 `B级.md`，S/A/C 级页面被引用但从未创建
- `tools/推荐层/分类/` 只有 3 个分类页，被引用的更多

## 四、待决策

1. `maintenance/reports/` 下的 `weekly-health` / `monthly-cleanup` /
   `quarterly-cleanup` 是脚本自动生成的报告，目前算严格区，
   缺 frontmatter 就会让门禁变红。要么给生成器补 frontmatter 模板，
   要么把这三类挪进 `history/`。
2. 历史阶段报告（`第X阶段完成报告` 等）的链接指向当时的文件，
   已随重构失效。是逐条修复，还是整体归入 `history/` 冻结。
3. `tools/检索层/按评级/` 与 `tools/推荐层/分类/` 的缺失页面：
   是补齐页面，还是删掉引用。
