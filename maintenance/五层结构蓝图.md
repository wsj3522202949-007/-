# 🏛️ 五层结构蓝图（L0–L4）——知识库的骨架

> 本知识库的**全部内容**都挂在一条「五层结构」上。它是架构，也是导航纪律的根。每层只干自己的活，越层就乱。
>
> 📌 本文件从原《维护标准》拆出，专司架构定义；不变量契约与维护仪式见 [维护标准.md](维护标准.md)，目录与命名守则见 [目录与命名规范.md](目录与命名规范.md)。

```
L0 总地图      README.md                           唯一前门：只做三件事（见下）
 │  不改名、不删区
 ├─ L1 项目门面   projects/你的书名/README.md            一本书的"首页"
 ├─ L2 正文层     projects/你的书名/正文/第NNN章-标题.md  一章一文件，只放最终稿
 ├─ L2 知识单页层 projects/你的书名/人物|设定|地点|道具/每一条一页  带 frontmatter，vault 相对路径互链
 ├─ L2 工作流层   人物设定卡 / 分卷细纲 / 伏笔管理表 / 写作进度 / 作战卡  只存"怎么写"的决策
 ├─ L3 素材仓     archive/                              灵感/截图/原始稿/外部资料（允许死链，进仓前先确认来源）
 └─ L4 工具与门禁 schema/维护标准.md · tools/scripts/validation/校验脚本.py · ../methods/工具/链接体检与修复.py  质量守门员（不是可选项）
```

### 各层职责与硬规则

- **L0 总地图（`README.md`）——只做三件事**：① 说明五大区（库 / 方法论 / archive / projects / 维护）；② 项目总表（所有书的书名·类型·状态·入口）；③ 30 秒速查表（想做 X → 去 Y）。**不改名、不删区**。其余入口都是从这里分出去的子地图。

- **L1 项目门面（`projects/你的书名/README.md`）——一本书的"首页"**：必须写卷名、当前进度、核心人物、主线冲突、章节映射。带 `tags: [type/project, area/项目, status/...]`。

- **L2 正文层（`正文/第NNN章-标题.md`）——一章一文件，只放最终稿**：每章**必须带 frontmatter**，且为 **ERROR 级强制机检**（见 `[F]` 与下表）——缺 frontmatter / 缺必填键 / `type` 非 `type/chapter` / `chapter` 序号与文件名不一致，均直接 ERROR，提交被阻断。不合并多章、不存草稿/素材。（命名契约见 [维护标准.md](维护标准.md) §1.5 ①）

- **L2 知识单页层（`人物/` `设定/` `地点/` `道具/`）——每个条目一页，带 frontmatter，用标准 markdown 链接互链，形成知识网**：
  - ✅ `[沈念](projects/你的书名/人物/沈念.md)`（标准 markdown 链接，AI/RAG 可稳定消费）
  - ❌ `[[沈念]]`（Obsidian 短名 wikilink，多数解析器不识别，链接体检脚本按文件路径解析会判断链）
  - 正文里用 markdown 链接串起人物/设定/地点/道具，以后改设定、查伏笔、查人物才方便。
  - 🚧 **不串味（书与书隔离）**：知识单页层链接**只在本项目内互链**（目标路径以 `projects/<本书名>/` 开头），**不得链到别的书**；每本书的 人物/设定/地点/道具 目录完全独立，互不可见；且这些目录**必须位于 `projects/<书名>/` 内，不得下沉到 vault 根**（见 [维护标准.md](维护标准.md) §1.5 ②）。
  - 📎 链接引用方式详见 [链接规范.md](链接规范.md)（标准 markdown 链接 / `related` / `see_also` 三种方式）。

- **L2 工作流层**——`人物设定卡.md` `分卷细纲.md` `伏笔管理表.md` `写作进度.md` `模板应用/作战卡.md`：它们**不存正文**，只存"怎么写"的决策与进度。

- **L3 素材仓（`archive/`）——灵感 / 截图 / 原始稿 / 外部资料**：**这里允许死链**（素材多来自外部、易失效），但**进 archive 前先确认来源**（作者 / 链接 / 日期），方便溯源。

- **L4 工具与门禁**——`schema/维护标准.md`（本契约）+ `tools/scripts/validation/校验脚本.py`（机检）+ `../methods/工具/链接体检与修复.py`（链接）。它们是质量守门员，**提交前必跑，不是可选项**。

### 按层 frontmatter 规范

| 层 | 文件 | 必带 frontmatter |
|---|---|---|
| L1 | `projects/书名/README.md` | `type: project` · `area: 项目` · `status: ...`（旧格式 `tags: [type/project, area/项目]` 过渡期 WARN） |
| L2 正文 | `正文/第NNN章-标题.md` | **强制** `title` · `chapter` · `status` · `type: chapter`（旧格式 `type: type/chapter` 过渡期 WARN；+ 建议 `pov`） |
| L2 知识 | `人物/设定/地点/道具/xxx.md` | `title` · `type: (character/setting/location/prop)` · `area: 项目` · `status: ...`（可加 `pov`/`kind`/`related`） |
| L2 工作流 | `人物设定卡/分卷细纲/伏笔管理表/写作进度` | 不强求，建议 `type: ref` · `area: 项目` |
| L3 | `archive/**` | 不强求；允许无 frontmatter、允许死链；**frontmatter 规范豁免** |
| L4 | `tools/scripts/validation/校验脚本.py`（不带 `_` 前缀，需版本化） | — |

> ⚠️ `type` `area` `status` 写成**独立 YAML 平键**（`type: ref`），不塞进 `tags`。`platform` `genre` `pov` `chapter` `kind` 等也写成独立 YAML 键。`tags` 只放纯关键词标签。完整 schema 见 [frontmatter规范.md](frontmatter规范.md)。

### 门禁顺序（提交前必跑）

1. `tools/scripts/validation/校验脚本.py` —— 守不变量契约（标签命名空间 / 结构 / 关键链接）。ERROR=0 才能提交。
2. `../methods/工具/链接体检与修复.py --fix` —— 守 markdown 链接 + 残留 wikilink（按 vault 相对路径解析）+ 顺手转义文件名里的 `_`。
3. `../methods/工具/docx_to_md.py` —— 入库前批量把 .docx 转清洗后 Markdown（pandoc 优先、python-docx 回退；删页眉/页脚/页码、删分页符、合并软回车、连续空行压一行、统一标题格式）。
4. `../methods/工具/ingest_chapters.py` —— 把清洗后 Markdown 最终稿落入 `正文/`：按章节标题拆分 → 命名 `第NNN章-标题.md`（序章为 `第000章-引子.md`）→ 逐章注入强制 frontmatter（`title/chapter/status/type:type/chapter/pov/tags`）→ 落库。用法：`python ingest_chapters.py <稿.md 或 目录> --project <projects/书名> [--pov 主角] [--status wip] [-f] [--dry-run]`。标准入库链路：**docx_to_md → ingest_chapters → 校验脚本(须 PASS) → 链接体检 --fix**。
> pre-commit 钩子已自动串起这两步（见 [维护标准.md](维护标准.md) §三 维护仪式）。
