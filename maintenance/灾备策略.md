## 📁 文件分类与维护策略

### 分类原则

知识库文件按生成方式分为三类：

| 类别 | 定义 | 维护策略 | 示例 |
|---|---|---|---|
| **自动生成文件** | 由脚本、工具自动生成的文件 | 可随时删除重建 | 报告、统计、索引 |
| **人工创作文件** | 用户手动创建、编辑的内容 | 需要版本控制、备份 | 章节、设定、大纲 |
| **配置文件** | 系统、工具配置文件 | 需要版本控制 | frontmatter、schema |

---

### 自动生成文件维护策略

**特征**：
- 由脚本生成（如 `生成首页统计.py`、`每周健康报告.py`）
- 内容可完全从源文件重新生成
- 不需要长期保留历史版本

**维护规则**：
1. **可删除**：如果源文件存在，可以随时删除自动生成文件
2. **可重建**：运行相应脚本即可重新生成
3. **不需要 Git 跟踪**：避免仓库膨胀
4. **定期清理**：每季度清理一次，保留最近 3 个月

**自动生成文件清单**：

| 文件/目录 | 生成脚本 | 清理周期 |
|---|---|---|
| `reports/` | 各种报告脚本 | 每季度压缩 |
| `tools/scripts/validation/__pycache__/` | Python 运行时 | 随时清理 |
| `index.json` | `生成首页统计.py` | 可随时重建 |
| `.DS_Store` | macOS | 随时清理 |

**清理命令**：
```bash
# 清理 Python 缓存
python tools/scripts/maintenance/季度清理.py --execute

# 重建索引
python tools/scripts/生成首页统计.py --update-readme
```

### 人工创作文件维护策略

**特征**：
- 用户手动创建、编辑
- 内容具有唯一性，无法自动重建
- 需要长期保留历史版本

**维护规则**：
1. **必须 Git 跟踪**：所有人工创作文件必须纳入 Git 版本控制
2. **必须备份**：定期备份到异地
3. **必须校验**：提交前运行核心校验
4. **必须标签**：重要里程碑打 Git 标签
5. **禁止直接删除**：删除前必须先归档到 `archive/`

**人工创作文件清单**：

| 文件/目录 | 重要性 | 备份频率 | 备注 |
|---|---|---|---|
| `projects/` | P0 | 实时备份 | 核心资产 |
| `methods/` | P0 | 实时备份 | 方法论资产 |
| `knowledge/` | P1 | 每日备份 | 知识资产 |
| `ai/` | P1 | 每日备份 | AI 工作流 |
| `goals/` | P1 | 每日备份 | 目标与复盘 |
| `schema/` | P0 | 实时备份 | 规范文件 |
| `maintenance/` | P1 | 每周备份 | 维护文档 |

**维护命令**：
```bash
# Git 提交（必须带校验）
python tools/scripts/maintenance/提交前校验.py && git add -A && git commit -m "feat: xxx"

# Git 推送（异地备份）
git push origin main

# Git 标签（里程碑）
git tag -a v1.0 -m "里程碑：完成第一卷"
```

### 配置文件维护策略

**特征**：
- 系统、工具配置文件
- 变更频率低
- 影响范围大

**维护规则**：
1. **必须 Git 跟踪**：配置文件纳入版本控制
2. **变更必须记录**：修改配置必须写 commit message
3. **禁止随意修改**：修改前必须了解影响
4. **备份配置文件**：定期备份到异地

**配置文件清单**：

| 文件 | 作用 | 变更频率 |
|---|---|---|
| `schema/frontmatter规范.md` | Frontmatter 规范 | 低 |
| `schema/目录与命名规范.md` | 目录命名规范 | 低 |
| `schema/维护标准.md` | 维护标准 | 低 |
| `CLAUDE.md` | AI 协作规范 | 中 |
| `.gitignore` | Git 忽略规则 | 低 |

## 🛡️ 备份策略

### 备份级别

```
L0: 工作区（实时）
  └── 本地磁盘 e:\个人知识库\

L1: 本地 Git 仓库（实时）
  └── e:\个人知识库\.git\

L2: 本地备份（每日）
  └── D:\备份\个人知识库\（外部硬盘）

L3: 异地备份（实时）
  └── GitHub/Gitee 私有仓库

L4: 快照备份（每周）
  └── Git 标签 + 压缩包
```

### 备份流程

#### 自动备份（推荐）

**工具**：Git + GitHub/Gitee 私有仓库

**配置步骤**：

1. **创建私有仓库**
   - GitHub: 创建私有仓库 `private-knowledge-base`
   - 或 Gitee: 创建私有仓库 `private-knowledge-base`

2. **添加远程仓库**
   ```bash
   git remote add origin git@github.com:yourname/private-knowledge-base.git
   # 或
   git remote add origin https://gitee.com/yourname/private-knowledge-base.git
   ```

3. **配置 Git 用户信息**
   ```bash
   git config user.name "Your Name"
   git config user.email "your.email@example.com"
   ```

4. **推送初始代码**
   ```bash
   git push -u origin main
   ```

5. **设置自动推送（Windows 任务计划）**
   ```powershell
   # 创建每日自动推送任务
   schtasks /create /tn "GitAutoPush" /tr "cd e:\个人知识库 && git add -A && git commit -m 'auto: daily backup' && git push" /sc daily /st 23:00
   ```

#### 手动备份（备选）

**工具**：Robocopy + 压缩

**备份命令**：
```powershell
# 每日备份到外部硬盘
robocopy e:\个人知识库 D:\备份\个人知识库\ /E /XO /R:3 /W:5

# 每周压缩备份
Compress-Archive -Path e:\个人知识库 -DestinationPath D:\备份\个人知识库_ weekly.zip
```

## 🔄 恢复策略

### 恢复场景

| 场景 | 恢复时间 | 恢复方式 |
|---|---|---|
| 误删文件（未提交） | < 5分钟 | Git checkout |
| 误删文件（已提交） | < 5分钟 | Git revert |
| 硬盘损坏 | < 1小时 | 从异地备份克隆 |
| 换电脑 | < 2小时 | 克隆 + 配置 |
| 全库丢失 | < 4小时 | 克隆 + 恢复 + 校验 |

### 恢复流程

#### 场景 1：误删文件（未提交）

```bash
# 查看删除的文件
git status

# 恢复文件
git checkout -- <file_path>

# 或恢复所有未提交的更改
git checkout .
```

#### 场景 2：误删文件（已提交）

```bash
# 查看提交历史
git log --oneline

# 恢复文件到指定版本
git checkout <commit_hash> -- <file_path>

# 或 revert 整个提交
git revert <commit_hash>
```

#### 场景 3：硬盘损坏

```bash
# 1. 从异地备份克隆
git clone git@github.com:yourname/private-knowledge-base.git e:\个人知识库

# 2. 运行完整性校验
python tools/scripts/maintenance/提交前校验.py

# 3. 修复问题（如有）
python tools/scripts/validation/_run_link_fixed.py --fix

# 4. 配置 Git
cd e:\个人知识库
git remote set-url origin git@github.com:yourname/private-knowledge-base.git
```

#### 场景 4：换电脑

参考《换电脑恢复说明书》

## 💻 换电脑恢复指南

### 前提条件

- 新电脑已安装 Git
- 新电脑已安装 Python 3.8+
- 有 Git 仓库访问权限

### 恢复步骤

#### 步骤 1：安装基础软件

```powershell
# 安装 Git（从 https://git-scm.com/ 下载）
# 安装 Python（从 https://www.python.org/ 下载）

# 验证安装
git --version
python --version
```

#### 步骤 2：克隆知识库

```powershell
# 克隆私有仓库
git clone git@github.com:yourname/private-knowledge-base.git e:\个人知识库

# 或使用 HTTPS
git clone https://github.com/yourname/private-knowledge-base.git e:\个人知识库
```

#### 步骤 3：配置环境

```powershell
# 进入目录
cd e:\个人知识库

# 配置 Git 用户信息
git config user.name "Your Name"
git config user.email "your.email@example.com"

# 安装 Python 依赖（如有）
pip install -r tools/requirements.txt
```

#### 步骤 4：验证完整性

```powershell
# 运行核心校验
python tools/scripts/maintenance/提交前校验.py

# 检查项目结构
dir projects
dir methods
dir schema
```

#### 步骤 5：恢复配置

```powershell
# 配置 Git 远程
git remote set-url origin git@github.com:yourname/private-knowledge-base.git

# 配置自动备份（可选）
# 参考备份策略章节
```

#### 步骤 6：恢复完成

```powershell
# 验证关键文件
python tools/scripts/validation/校验脚本.py --json

# 开始使用
echo "✅ 知识库恢复完成！"
```

## 🔍 误删文件找回

### Git 恢复方法

#### 方法 1：未提交的文件

```bash
# 恢复单个文件
git checkout -- <file_path>

# 恢复所有未提交的文件
git checkout .
```

#### 方法 2：已提交的文件

```bash
# 查看历史
git log --oneline --all -- <file_path>

# 恢复文件到指定版本
git checkout <commit_hash> -- <file_path>

# 查看文件历史
git log -p -- <file_path>
```

#### 方法 3：删除的文件

```bash
# 查看所有删除的文件
git log --diff-filter=D --summary

# 恢复删除的文件
git checkout <commit_hash>^ -- <file_path>
```

### 恢复时间承诺

| 场景 | 恢复时间 | 成功率 |
|---|---|---|
| 未提交文件 | < 5分钟 | 100% |
| 已提交文件 | < 5分钟 | 100% |
| 已 push 到远程 | < 5分钟 | 100% |
| 本地仓库损坏 | < 1小时 | 100% |
| 远程仓库也删除 | < 24小时 | 视备份情况 |
