## 🎯 创作流程概览

### 完整闭环
```
我要写下一章
    ↓
1. 找细纲（outline-第一卷.md）
    ↓
2. 写草稿（参考人物卡、系统设定）
    ↓
3. 正文自检（自检清单_升级版.md）
    ↓
4. 去 AI 味处理（最强去AI味铁律.md）
    ↓
5. 移入正式章节（chapters/）
    ↓
6. 更新项目进度（STATUS.md）
    ↓
7. 追读/完读复盘（定期）
    ↓
完成，准备下一章
```

### 时间预估
- 找细纲：2分钟
- 写草稿：2-3小时
- 正文自检：30分钟
- 去 AI 味处理：30分钟
- 移入正式章节：5分钟
- 更新项目进度：5分钟
- **总计**：3.5-4.5小时/章

## 🔴 痛点记录与自动化

### 痛点 1：找细纲要翻多个文件

**问题**：
- 细纲分散在 `outline.md`、`outline-前三章.md`、`outline-第一卷.md`
- 需要人工判断当前写到哪了
- 容易找不到下一章的细纲

**现状**：
```markdown
当前状态：
- outline.md：总大纲（四卷结构）
- outline-前三章.md：黄金三章详细设计
- outline-第一卷.md：第一卷30章细纲

需要人工判断：
- 目前写了10章
- 下一章应该是第11章
- 需要打开 outline-第一卷.md
- 找到第11章的细纲
```

**痛点**：
- ❌ 需要人工记忆当前进度
- ❌ 需要打开多个文件查找
- ❌ 容易找错细纲
- ❌ 浪费时间（每次2-5分钟）

**自动化方案**：
创建 `tools/scripts/创作闭环助手.py`，自动：
1. 读取 STATUS.md，获取当前进度
2. 读取 outline-第一卷.md，提取下一章细纲
3. 自动打开细纲文件
4. 生成创作模板

**脚本功能**：
```bash
# 获取下一章细纲
python tools/scripts/创作闭环助手.py --next-chapter

# 生成创作模板
python tools/scripts/创作闭环助手.py --template 11

# 更新进度
python tools/scripts/创作闭环助手.py --update-progress 11
```

### 痛点 2：重复填写章节信息

**问题**：
- 每章 frontmatter 需要填写：
  - id（如 `ch011`）
  - title（章节标题）
  - chapter（章节号）
  - volume（卷号）
  - word_count（字数）
  - tags（标签）
  - summary（摘要）
  - related（关联文件）

**现状**：
```markdown
---
id: ch001
type: chapter
area: 项目
status: draft
tags: [第一章, 重生, 系统激活]
title: 第一章：重生觉醒
summary: 林辰重生回2010年...
word_count: 3000
created: 2026-08-02
updated: 2026-08-02
chapter: 1
volume: 1
---
```

**痛点**：
- ❌ 需要手动填写 id（容易写错）
- ❌ 需要手动填写 chapter 和 volume
- ❌ 需要手动填写 tags
- ❌ 需要手动填写 summary
- ❌ 容易漏填字段
- ❌ 格式不统一

**自动化方案**：
创建章节模板生成器，自动：
1. 根据章节号生成 id（`ch011`）
2. 自动设置 chapter 和 volume
3. 从细纲提取 tags
4. 从细纲提取 summary
5. 生成标准 frontmatter

**模板示例**：
```markdown
---
id: ch{chapter:03d}
type: chapter
area: 项目
status: draft
tags: [第{chapter}章, {tags from outline}]
title: 第{chapter}章：{title from outline}
summary: {summary from outline}
word_count: 0
created: {date}
updated: {date}
chapter: {chapter}
volume: {volume}
---
```

### 痛点 3：AI 加载项目上下文困难

**问题**：
- AI 需要知道当前项目的人物、设定、大纲
- 但 AI 无法自动加载项目上下文
- 需要手动复制粘贴大量信息
- 容易串戏（把其他小说的人物或设定带进来）

**现状**：
```markdown
写作时：
1. 打开 AI 对话
2. 手动复制 framework.md
3. 手动复制人物卡
4. 手动复制系统设定
5. 手动复制当前细纲
6. 提示 AI："基于以上设定写第11章"

问题：
- ❌ 复制粘贴工作量大
- ❌ 容易漏掉重要设定
- ❌ AI 可能混淆不同项目的设定
- ❌ 容易串戏
```

**痛点**：
- ❌ 人工寻找路径（需要打开多个文件）
- ❌ 重复填写（需要复制多个文件）
- ❌ 容易出错（容易串戏）
- ❌ 效率低（每次10-15分钟）

**自动化方案**：
创建项目上下文加载器，自动：
1. 读取项目目录
2. 提取 framework.md
3. 提取所有人物卡
4. 提取系统设定
5. 提取当前细纲
6. 生成标准化的项目上下文

**AI 提示词模板**：
```
你是网文写作助手。现在你要基于以下项目设定写第11章。

【项目设定】
{framework.md}

【人物卡】
{all character cards}

【系统设定】
{system setting}

【当前细纲】
{current chapter outline}

【写作要求】
1. 严格基于以上设定
2. 不要引入其他项目的设定
3. 保持人物性格一致
4. 遵循细纲结构
5. 去 AI 味处理
```

### 痛点 4：自检流程不标准

**问题**：
- 自检清单很长（100+项）
- 需要逐项检查
- 容易漏检
- 没有标准化的检查流程

**现状**：
```markdown
自检清单包含：
- 细纲与章节结构检查（7项）
- 主角与契约检查（6项）
- 情绪与爽点检查（6项）
- 对白检查（5项）
- 世界观与设定检查（5项）
- AI 味检查（14类禁用表达）
- 平台规范检查（5项）
- 纪律检查（5项）

总计：50+项检查
```

**痛点**：
- ❌ 检查项太多，容易漏检
- ❌ 没有优先级，不知道先检查什么
- ❌ 检查结果没有记录
- ❌ 容易重复检查

**自动化方案**：
创建自检助手，自动：
1. 按优先级分组检查
2. 生成检查报告
3. 标记问题项
4. 提供修改建议

**检查流程**：
```
第一步：硬性检查（10分钟）
- 细纲完整性
- 章节结构
- 字数达标

第二步：情绪检查（10分钟）
- 爽点密度
- 情绪曲线
- 章末钩子

第三步：AI味检查（10分钟）
- 禁用表达
- 表演腔
- 总结先行

第四步：平台规范（5分钟）
- 番茄规范
- 格式要求

第五步：生成报告
- 问题清单
- 修改建议
- 通过/不通过
```

3. 提供修改建议

第二步：自动修改
- 替换禁用表达

## 🔧 故障排除

### 问题 1：找不到下一章细纲

**解决**：
1. 检查 STATUS.md，确认当前章节
2. 检查 outline-第一卷.md，确认细纲存在
3. 运行 `python tools/scripts/创作闭环助手.py --next-chapter`

### 问题 2：AI 生成内容串戏

**解决**：
1. 检查项目上下文是否正确加载
2. 确认人物卡和系统设定已包含
3. 在 AI 提示词中强调"不要引入其他项目的设定"

### 问题 3：自检查不完

**解决**：
1. 按优先级分组检查
2. 先完成硬性检查（必须通过）
3. 再完成情绪检查
4. 最后完成 AI 味检查

### 问题 4：去 AI 味效果不明显

**解决**：
1. 使用 `methods/最强去AI味铁律.md` 的完整清单
2. 逐句检查禁用表达
3. 朗读检查，听是否自然
4. 增加个人风格和口语化表达
