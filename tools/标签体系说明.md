# 🏷️ 标签体系说明（情报网字段字典）

> ↩ **回总地图**：[🗺️ 知识库总地图](../README.md)
> 每篇工具卡（tools/cards）的 frontmatter 现在含 4 个「可用」字段。含义如下。

## tier（分层 · 优先度）

- `S` 主力推荐（151 篇）— Stars≥200，社区验证过，**优先试用**
- `A` 靠谱备选（107 篇）— Stars 50–199，质量稳
- `B` 长尾观察（1382 篇）— Stars 1–49，小众/新库，按需挖
- `C` 存疑待验（1949 篇）— 0★ 或源仓库无 README，**试用前先小范围测**

## tags（标签 · 维度过滤）

> `tags` 字段 = **能力 + 技术 + 协议 + 部署 + 文档** 五类。**领域/分类信息在 `category` 字段**（Obsidian 同样可按属性过滤），不放进 tags，以免与能力标签重名导致误收。

- **能力**：`去AI味` `RAG` `多Agent` `提示词` `大纲规划` `TTS` `Claude插件` `校对` `互动叙事` `文风迁移`
- **技术**：`Python` `JavaScript` `TypeScript` `HTML` `Java` `Go` `C#` …（实现语言，判断你能否跑/改）
- **协议**：`协议宽松`(MIT/Apache/BSD/CC0 等，可放心用) · `协议传染`(GPL/AGPL，商用/闭源分发需谨慎) · `协议未明`(未声明，商用前确认)
- **部署**：`需API密钥`(要自备 LLM Key，有 token 成本) · `本地优先`(正文未检出 Key 依赖，倾向可本地跑)
- **文档**：`中文友好`(有中文资料) · `英文文档`(需一定英文阅读力)

## use_case（使用场景 · 何时用它）

> 一句话说明这个工具最适合干什么，按分类默认 + 正文关键词细化。进工具卡即可看到。

## pitfalls（避坑 · 上手前必看）

> 自动检出的风险信号，常见几种：
- `⚠️ 源仓库无 README，功能未经核验…` — 347 篇空壳，先看作者其他仓库或 demo
- `⚠️ 0 stars，未经社区验证…` — 先小范围测试
- `🔑 需自备 LLM API Key…` — 有 token 成本与网络门槛
- `⚠️ 协议带传染性（GPL/AGPL）…` — 商用前评估合规
- `⚠️ 协议未声明…` — 商用前到仓库确认授权
- `⚠️ 仓库疑似停更/归档…` — bug 不会修、依赖可能过期
