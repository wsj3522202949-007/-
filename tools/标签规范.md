# 🏷️ 标签规范（两套并行体系 · 受控注册表）

> 本库有两套**互不冲突**的标签，分清楚就不会乱：
> - **工具卡 `tags`** —— 在 `./cards/*.md` 里，按「能力/技术/协议/部署/文档」给 3572 篇工具打标，用来**按维度筛工具**。
> - **笔记层 `tags`** —— 在 `./`、`../methods/`、`projects/` 的导航/方法/项目笔记里，用命名空间 `type/ area/ status/` 打标，用来**在整个 vault 导航 + 驱动仪表盘**。
>
> 两者都写在 YAML frontmatter 的 `tags:` 字段，Obsidian 会合并进同一个「标签窗格」，靠**命名空间**区分：工具卡的标签没有 `/`，笔记层的标签都有 `/`。

> ⚠️ **诚实边界**：工具卡标签由 `_enrich_readmes.py` 自动派生，源库本身约 1–2% 误分类，个别标签可能不精准；笔记层标签全部是人工维护的受控词，可信。

---

## 一、工具卡 `tags`（5 维度 · 受控）

> 字段含义见 [标签体系说明](标签体系说明.md)。下面给出**受控词注册表**——协议/部署/文档/能力 四组只能从表中取值，技术组开放（实现语言）。
> **领域信息（如「长篇 AI 写作系统」「降AI工具」）不进 `tags`，留在 `category` 字段**，否则会和同名能力标签互相误收。

### 1.1 协议（3 个 · 受控）

| 标签 | 含义 | 商用建议 |
|---|---|---|
| `协议宽松` | MIT / Apache / BSD / CC0 / ISC / MPL / Unlicense 等 | 放心用、可闭源分发 |
| `协议传染` | GPL / AGPL / LGPL | 商用/闭源分发前评估合规（AGPL 最严） |
| `协议未明` | 仓库未声明 License | 商用前到仓库确认授权 |

### 1.2 部署（2 个 · 受控）

| 标签 | 含义 |
|---|---|
| `本地优先` | 正文未检出 API Key 依赖，倾向可本地跑、隐私可控 |
| `需API密钥` | 需自备 LLM Key，有 token 成本与网络门槛 |

### 1.3 文档（2 个 · 受控）

| 标签 | 含义 |
|---|---|
| `中文友好` | 有中文资料 / 中文 README |
| `英文文档` | 需一定英文阅读力 |

### 1.4 能力（15 个 · 受控）

| 标签 | 对应写作场景 |
|---|---|
| `去AI味` | 投稿前正文降 AI 痕、过检测（**你的签约痛点对应工具**） |
| `RAG` | 长篇人物/设定/伏笔一致性记忆 |
| `多Agent` | 多 Agent 协作自动产文 |
| `提示词` | 提示词 / 写作工作流模板 |
| `大纲规划` | 搭大纲 / 分卷 / 节拍板 |
| `TTS` | 小说转语音 / 有声化 |
| `互动叙事` | 互动叙事 / 聊天 Bot 写故事 |
| `校对` | 错别字 / 语法 / 风格校对 |
| `文风迁移` | 模仿某作者/平台文风 |
| `Claude插件` | Claude Code / CodeBuddy 插件类 |
| `人物设定` | 角色设计 / 人设卡 / 人物弧光 |

> 能力标签只从「最后一个 `---` 后的真实正文 + 上游英文描述」抽取，**排除含分类名的中文元数据块**（规则固化在 `_enrich_readmes.py` 的 `离题守卫` 与 `真实正文` 截取里）。

### 1.6 技术（开放 · 实现语言）

- 取值 = 该仓库检测到的**实现语言**，如 `Python` `JavaScript` `TypeScript` `Go` `Rust` `HTML` `Java` `C#` `Vue` `Jupyter Notebook` …
- **命名规则**：尽量小写 ASCII；语言名本身含空格的保留原样（如 `Jupyter Notebook`）；**不要**为「技术」自造语义标签（如别写 `大模型` `前端` 这种——那该进能力组或类别）。

### 1.7 工具卡命名硬规则

1. 协议 / 部署 / 文档 / 能力 四组**只用上表 canonical 值**，禁止自由发挥（如别写 `免费` 代替 `本地优先`）。
2. 技术标签 = 实现语言，小写优先。
3. 标签间禁止空格（YAML 列表 `[A, B]` 已天然保证）。
4. 领域信息不进 `tags`，留在 `category`。
5. 一个工具可同时带多个维度标签（例：`[TypeScript, 协议宽松, 本地优先, 英文文档]`）。

## 二、笔记层 `tags`（命名空间 · 受控）

> 用在 `./`、`../methods/`、`projects/` 的**笔记**上（不是工具卡），让标签窗格成为导航面、让仪表盘能列出「工作台模块」。

### 2.1 命名空间

| 前缀 | 取值 | 含义 |
|---|---|---|
| `type/` | `index` `guide` `ref` `dashboard` `template` `moc` `demo` `project` | 笔记性质 |
| `area/` | `库` `方法` `项目` | 所属工作台分区 |
| `status/` | `active` `demo` `wip` `done` | 状态（可选） |

### 2.2 完整取值表

| 标签 | 贴在哪种笔记 |
|---|---|
| `type/index` | 总地图 / 入口（根 README） |
| `type/guide` | 怎么做（选型指南、QUICK_START） |
| `type/ref` | 参考/规范（标签体系说明、标签规范、模板库） |
| `type/dashboard` | 仪表盘 |
| `type/template` | 模板库 / 单页模板 |
| `type/moc` | 分类导航 MOC |
| `type/demo` | 示范项目说明 |
| `type/project` | 真实项目说明 |
| `area/库` | 工具情报网相关 |
| `area/方法` | 方法论 / 模板相关 |
| `area/项目` | projects/ 下项目相关 |
| `status/demo` | 仅示范、非真书 |
| `status/active` | 在写 |
| `status/wip` | 草稿中 |
| `status/done` | 已完成 |

### 2.3 笔记层命名硬规则

1. **全小写**（唯一例外：`area/` 取值为中文 `库 / 方法 / 项目`，这是命名空间设计的一部分，非自由中文），`/` 分层，**禁止空格**（保持标签窗格干净、可分层折叠）。
2. 每条笔记**恰好一个** `area/` 标签（它同时是仪表盘「工作台模块」查询的伞形标签）。
3. `type/` 与 `status/` 可按需组合（示范项目 = `type/demo` + `status/demo`）。
4. 工具卡**绝不**使用 `type/ area/ status/` 命名空间——两套靠 `/` 区分。

## 三、Dataview 怎么用这两套标签

**按能力筛工具（工具卡 tags）：**
```dataview
TABLE stars, use_case, tier FROM "tools/cards"
WHERE contains(tags, "去AI味") AND tier IN ("S","A")
SORT stars DESC
```

**列出工作台所有模块（笔记层 area/ 伞形）：**
```dataview
LIST FROM "" WHERE contains(tags,"area/库") OR contains(tags,"area/方法") OR contains(tags,"area/项目")
SORT file.link
```

**只列出分类导航 MOC：**
```dataview
LIST FROM "库/分类导航" WHERE contains(tags,"type/moc") SORT file.link
```

## 四、反例（别这样）

| ❌ 错误 | ✅ 正确 | 原因 |
|---|---|---|
| 工具卡写 `tags: [免费]` | `tags: [本地优先]` | 协议/部署组只能用受控词 |
| 工具卡写 `tags: [前端]` | 写实现语言 `tags: [JavaScript]` 或能力 `tags: [提示词]` | 技术=语言，语义进能力/类别 |
| 工具卡写 `tags: [长篇AI写作]` | 留在 `category:` 字段 | 领域不进 tags，防误收 |
| 笔记写 `tags: [模板]` | `tags: [type/template, area/方法]` | 笔记层必须命名空间化 |
| 笔记写 `tags: [Type/模板]` | `tags: [type/template]` | 全小写、禁大写禁中文 |

## 五、维护

- **新增工具卡**：跑 `_enrich_readmes.py` 自动派标，受控词保证一致；不手动改 tags。
- **新增笔记**：手动在 frontmatter 加 `type/ area/`（`status/` 可选），从本表取值。
- 本规范与 [标签体系说明](标签体系说明.md)（字段字典）、[工具选型指南](工具选型指南.md)（任务→工具）、`[仪表盘](../仪表盘.md)`（实时统计）互锁。
