# 🛠️ 库·维护说明（这个情报网怎么养）

> 本文件讲清楚 `./` 这套 AI 写作工具情报网**是怎么来的、标签怎么派、怎么加新卡、怎么刷新统计、怎么去噪**。写给要维护/扩库的人。日常「按约束挑工具」请看 [库·落地建议](落地建议.md)；项目级不变量见 `[维护标准](../../schema/维护标准.md)`。

---

## 一、这个库是什么

- **3572 张工具卡**（`./cards/*.md`）+ **21 张分类导航 MOC**（`./分类导航/`）+ 入口层（`知识库导航` / `工具选型指南` / `标签规范` / `标签体系说明`）。
- 来源：从 GitHub 拉取的真实 AI 写作开源项目，经 `_enrich_readmes.py` 抽取成统一卡片。
- 性质：**派生数据**。卡片是脚本生成的；真正「人写的判断」在 `工具选型指南` / `落地建议` / 各 MOC 的 verdict 里（情报层），不在卡片 frontmatter。

---

## 二、数据流水线

```
GitHub 仓库列表
   │  _enrich_readmes.py（抽取 + 派标 + 写卡）
   ▼
库/cards/<no>__<owner>__<repo>.md
   │   frontmatter: no / category / repo / stars / tier / tags / use_case / pitfalls
   │   body: 分类 / 链接 / Stars / 语言 / License / Topics / GitHub描述 / 本地描述 / 拉取时间
   ▼
仪表盘-静态版.md  ←─  _仪表盘_快照.py（扫描 frontmatter，生成零依赖快照）
```

- **文件名规则**：`<no>__<owner>__<repo>.md`，`no` 是抓取序号，`owner/repo` 是仓库坐标。
- **tier 初筛**：默认由 `stars` 划档（S/A/B/C），但 **S/A 级必须经人工 verdict 确认**才算数（见第六节）。
- **用法说明**：`use_case` / `pitfalls` 多为自动抽取，**模板套话、避坑常空**——别当真情报。

---

## 三、标签体系（5 维度 · 受控）

> 完整注册表见 [标签规范](标签规范.md)。工具卡 `tags` 只从下表取值，保证可筛、可聚。

| 维度 | 受控词 | 作用 |
|---|---|---|
| 协议 | `协议宽松` / `协议传染` / `协议未明` | 商用红线 |
| 部署 | `本地优先` / `需API密钥` | 成本与隐私 |
| 文档 | `中文友好` / `英文文档` | 上手门槛 |
| 能力 | `去AI味` `RAG` `多Agent` `提示词` `大纲规划` `TTS` `互动叙事` `校对` `文风迁移` `Claude插件` | 按场景筛 |
| 技术 | 实现语言（Python/TS/…）开放 | 技术栈 |

- **领域信息不进 `tags`**，留在 `category` 字段（防同名能力标签误收）。
- 笔记层另有 `type/ area/ status/` 命名空间标签（与工具卡靠 `/` 区分），由人维护、可信。

---

## 四、怎么加新卡

1. 把新仓库加进抓取源列表。
2. **跑 `_enrich_readmes.py`** —— 自动抽取 frontmatter + 派标，**不要手改 `tags`**（下次重跑会被覆盖）。
3. 若某卡分类/层级明显错（误分类约 1–2%）：
   - 优先在**源数据**修；或
   - 接受「卡片 frontmatter 是派生数据」——把正确判断写进 `工具选型指南` / MOC verdict（情报层是耐久的，卡片是易碎的）。
4. 加完重跑 `_仪表盘_快照.py` 刷新统计（见第五节）。

---

## 五、怎么刷新统计

- 工具库变动后，跑：
  ```sh
  python _仪表盘_快照.py
  ```
- 生成 `仪表盘-静态版.md`（零依赖真实数字）。这是**维护仪式**的一环（见 `[维护标准](../../schema/维护标准.md)`）。
- 装了 Dataview 插件时，`仪表盘.md` 的 dataview 查询会实时刷新，无需跑脚本。

---

## 六、去噪与质控

- **误分类**：源库约 1–2% 把非写作仓库塞进写作类（如机器人 SDK、W3C 文档）。识别法：看 `category` 与 `tags` 是否真沾写作；高星但 `use_case` 是套话的多半要复核。
- **情报层才是可信判断**：`工具选型指南`（任务→工具）、`落地建议`（约束→组合）、各 MOC 的 verdict，是人工研判的落点；卡片 frontmatter 只做「能不能筛」的粗粒度。
- **S/A 须人工 verdict**：tier 初筛靠星标，噪声仓库也能进 S/A；只有经人工确认「真适合写文」的才计入推荐。

---

## 七、不变量（与项目级维护一致）

- 工具卡 `tags` 只用受控词；笔记层 `tags` 严格命名空间化（恰好一个 `area/`）。
- 全库只有一个前门 `README.md`；`./` 入口是 `知识库导航`，子地图必带 `↩ 回总地图`。
- 提交前跑 `[维护标准](../../schema/维护标准.md)` 里的 `校验脚本.py`（ERROR 阻断）+ 链接体检；详见项目维护机制。

---

## 八、刷新节奏建议

| 场景 | 动作 |
|---|---|
| 加/删一批工具卡后 | 跑 `_仪表盘_快照.py` 刷新静态版 |
| 每周例行 | 跑校验脚本 + 链接体检，追加 `[维护日志](../../schema/维护日志.md)` |
| 发现误分类 | 在情报层（选型指南/MOC）订正，必要时修源重跑富集 |
| 换机 / 重装 | clone 即恢复；Dataview 按需装，不装则用静态版 |
