Tiny Tales AI combines a React Native mobile app with a local LLM (via [Ollama](https://ollama.com)) and a Stable Diffusion image server to generate multi-page interactive storybooks tailored to a child's age, interests, and learning goals. No cloud subscriptions, no data sent to third parties.

## Features

- **Personalized stories** — choose from 12 themes, dozens of characters, moods, and age groups (3–10)
- **AI illustrations** — each story page gets a unique cartoon-style image generated by Stable Diffusion
- **Read aloud** — British English text-to-speech with word highlighting and a child-friendly voice
- **Comprehension quizzes** — per-page questions generated by the LLM to reinforce learning
- **Word helper** — glossary of tricky words with spell-out pronunciation
- **Story library** — save and revisit previous stories
- **Daily story scheduler** — send a notification at a set time to generate a fresh story automatically
- **Fully local** — all AI inference runs on your own hardware via Ollama and a local FastAPI server

---

## Models Used

- **Llama 3.1** for story generation, quizzes, and glossary support. Official Ollama model page: [ollama.com/library/llama3.1](https://ollama.com/library/llama3.1)
- **Stable Diffusion v1.5** for page illustrations via the backend image server. Model card: [huggingface.co/runwayml/stable-diffusion-v1-5](https://huggingface.co/runwayml/stable-diffusion-v1-5)

In this codebase, the default text model is set to `llama3.1` in [tiny-tales/App.js](/Users/rahul/vscode_projects/tiny-tales-ai/tiny-tales/App.js#L33), and the image backend loads `runwayml/stable-diffusion-v1-5` in [backend/server.py](/Users/rahul/vscode_projects/tiny-tales-ai/backend/server.py#L52).

## Architecture

```
┌─────────────────────────┐        LAN / localhost
│   React Native App      │ ──────────────────────────────────────────┐
│   (Expo / Android/iOS)  │                                           │
└─────────────────────────┘                                           │
          │                                                           │
          │  HTTP  ┌───────────────────────────┐                     │
          ├───────▶│  Ollama  (port 11434)      │  Story text, quizzes,
          │        │  Model: llama3.1 (default) │  glossary
          │        └───────────────────────────┘
          │
          │  HTTP  ┌───────────────────────────┐
          └───────▶│  FastAPI Image Server      │  Base64 PNG per page
                   │  (port 8000)              │
                   │  Model: SD v1.5            │
                   └───────────────────────────┘
```

The mobile app connects to both servers over your local network. You configure the host IP once inside the app settings.

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/your-username/tiny-tales-ai.git
cd tiny-tales-ai
```

### 2. Start the LLM (Ollama)

Install Ollama from [ollama.com](https://ollama.com), then pull the default model:

```bash
ollama pull llama3.1
ollama serve          # starts on http://localhost:11434
```

Any other Ollama-compatible model works — update the model name in the app settings.

### 3. Start the Image Generation Server

```bash
cd backend
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate

pip install -r requirements.txt   # first run only, downloads ~4 GB of model weights

uvicorn server:app --host 0.0.0.0 --port 8000
```

The API will be available at `http://localhost:8000`. Interactive docs: `http://localhost:8000/docs`.

> **Tip:** The Stable Diffusion weights are cached in `~/.cache/huggingface` after the first download.

### 4. Run the Mobile App

```bash
cd tiny-tales
npm install
npm start             # starts the Expo Metro bundler
```

Then press:
- `a` — open on a connected Android device or emulator
- `i` — open on the iOS Simulator (macOS only)
- `w` — open in a web browser (limited functionality)

Or scan the QR code with the **Expo Go** app on your phone.

### 5. Configure the Host IP

On first launch, open **Settings** (gear icon) in the app and set the **Host IP** to the local network IP of the machine running Ollama and the image server (e.g. `192.168.1.42`). If running everything on the same machine as an emulator, use `10.0.2.2` (Android) or `localhost` (iOS Simulator).

## Local Development with Android Studio

### Set up the Android environment

1. Download and install [Android Studio](https://developer.android.com/studio).
2. Open Android Studio → **SDK Manager** → install:
   - Android SDK Platform (API 34 recommended)
   - Android SDK Build-Tools
   - Android Emulator
3. Add the SDK to your shell profile:
   ```bash
   export ANDROID_HOME=$HOME/Library/Android/sdk       # macOS
   export PATH=$PATH:$ANDROID_HOME/emulator
   export PATH=$PATH:$ANDROID_HOME/platform-tools
   ```
4. Verify:
   ```bash
   adb --version
   ```

### Create a virtual device (AVD)

1. Open Android Studio → **Device Manager** → **Create Device**.
2. Choose a phone profile (e.g. Pixel 7) and a system image (API 34, x86_64).
3. Finish and start the emulator.

### Run on the emulator

```bash
cd tiny-tales
npm run android
```

Expo will build the debug APK and install it on the running emulator automatically.

### Run on a physical Android device

1. Enable **Developer Options** on your device (tap *Build Number* 7 times in Settings → About).
2. Enable **USB Debugging**.
3. Connect via USB — confirm the prompt on your device.
4. Verify the device is detected:
   ```bash
   adb devices
   ```
5. Run:
   ```bash
   npm run android
   ```

### Hot reload & debugging

- **Fast refresh** is on by default — save any file and the app updates instantly.
- Shake the device (or press `m` in the Metro terminal) to open the Expo developer menu.
- React DevTools: `npx react-devtools`
- Network inspector: open `http://localhost:8081` in a browser while Metro is running.

## Building a Release APK

### Using EAS Build (recommended)

```bash
npm install -g eas-cli
eas login
eas build --platform android --profile preview
```

This produces a standalone `.apk` / `.aab` via Expo's build servers.

### Local build (no EAS account needed)

```bash
# Install Expo's local build tooling
npx expo run:android --variant release
```

The signed APK will appear in `android/app/build/outputs/apk/release/`.

> A pre-built APK for v0.1 is available in [release/tiny-tales_v0.1.apk](release/tiny-tales_v0.1.apk).

## Configuration Reference

All runtime settings are persisted in `AsyncStorage` on the device — no `.env` file is required.

| Setting | Default | Where to change |
|---|---|---|
| Host IP | `192.168.0.143` | App Settings screen |
| LLM model | `llama3.1` | App Settings screen |
| TTS language | `en-GB` | `App.js` → `CHILD_VOICE_LANGUAGE` |
| Image server port | `8000` | `App.js` → API call URLs |
| Ollama port | `11434` | `App.js` → API call URLs |
