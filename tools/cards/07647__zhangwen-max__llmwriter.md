# 基于 RAG 的长篇小说智能创作系统

## 📖 项目概述

本项目是一个**基于 RAG（检索增强生成）技术的长篇小说智能创作系统**，旨在解决 AI 辅助创作长篇小说时面临的**上下文爆炸**和**前后章节关联性断裂**的核心痛点。

## 🎯 解决的痛点

### 1. **上下文爆炸问题**
- **问题描述**：当小说字数达到数万甚至数十万字时，将所有历史章节内容直接输入给 LLM 会导致：
  - Token 数量超出模型限制
  - 上下文窗口被占满，无法有效利用
  - 生成成本急剧上升
  - 响应速度显著下降

### 2. **前后章节关联性断裂**
- **问题描述**：在长篇小说创作中，AI 生成新章节时经常出现：
  - 忘记前文设定和伏笔
  - 角色性格前后不一致
  - 世界观设定被违反
  - 情节逻辑不连贯
  - 伏笔无法回收

## 💡 技术方案

### 核心技术栈

| 技术 | 作用 | 实现方式 |
|------|------|----------|
| **Qdrant 向量数据库** | 语义检索与记忆存储 | 将章节记忆向量化存储，支持语义相似度检索 |
| **LLM（大语言模型）** | 内容生成引擎 | 使用 Qwen-Plus 模型生成章节正文 |
| **RAG（检索增强生成）** | 上下文增强 | 根据当前章节需求，智能检索相关历史记忆 |
| **Prompt 工程** | 生成质量控制 | 精心设计的 Prompt 模板，确保生成内容符合要求 |
| **Python** | 系统实现语言 | 模块化架构，易于扩展和维护 |

### 核心架构

```
┌─────────────────────────────────────────────────────────┐
│                   章节生成流程                           │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 写作计划 → 2. RAG检索历史记忆 → 3. 构建Prompt      │
│                                                         │
│  4. LLM生成章节 → 5. 提取记忆 → 6. 存储到向量库        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 关键技术实现

#### 1. **分层记忆管理系统**
- **L1 层：世界观圣经** - 基础设定，贯穿全文
- **L2 层：角色卡** - 角色性格、能力、关系
- **L3 层：阶段摘要** - 每 5-10 万字压缩为摘要
- **L4 层：最近章节记忆** - 最近 3 章的结构化记忆
- **L5 层：上一章结尾** - 直接传递上一章后 3000 字，确保情节连贯

#### 2. **RAG 检索策略**
- **多路检索**：根据写作计划，同时检索：
  - 人物关系相关记忆
  - 地点/物品设定相关记忆
  - 开放伏笔相关记忆
- **智能压缩**：使用 LLM 将检索到的记忆压缩为简洁的事实清单
- **语义检索**：基于向量相似度，而非简单关键词匹配

#### 3. **记忆提取与存储**
- **自动提取**：每章生成后，自动提取：
  - 事件（Events）
  - 事实（Facts）
  - 关系（Relationships）
  - 伏笔（Hooks）
- **向量化存储**：将记忆转换为向量，存入 Qdrant
- **本地 Fallback**：Qdrant 不可用时，使用关键词匹配的本地策略

#### 4. **Prompt 工程**
- **系统 Prompt**：定义 AI 的角色、原则、风格要求
- **用户 Prompt**：包含：
  - 世界观圣经
  - 角色卡信息
  - 阶段摘要
  - RAG 检索的事实清单
  - 最近章节摘要
  - 上一章结尾
  - 本章写作计划

## 🚀 核心优势

### 1. **解决上下文爆炸**
- ✅ 不再需要将全部历史章节输入 LLM
- ✅ 只检索与当前章节相关的记忆（通常 10-20 条）
- ✅ Token 使用量减少 90% 以上
- ✅ 生成速度提升，成本大幅降低

### 2. **确保前后连贯**
- ✅ 通过 RAG 检索，确保重要设定和伏笔不被遗忘
- ✅ 分层记忆系统，不同层级的信息各司其职
- ✅ 直接传递上一章结尾，保证情节自然衔接
- ✅ 自动一致性校验，检测设定冲突

### 3. **提升创作质量**
- ✅ 角色性格保持一致
- ✅ 世界观设定不被违反
- ✅ 伏笔能够有效回收
- ✅ 情节逻辑连贯自然

## 📊 技术亮点

1. **可插拔向量库架构**：支持 Qdrant 和本地 Fallback，适应不同部署环境
2. **多路 RAG 检索**：针对不同信息类型采用不同检索策略
3. **智能记忆压缩**：使用 LLM 将大量记忆压缩为简洁事实清单
4. **完整日志系统**：记录所有 LLM 调用和向量库操作，便于调试和优化
5. **模块化设计**：各模块职责清晰，易于扩展和维护

## 🎓 技术价值

本项目展示了如何将 **RAG 技术**应用于**长文本生成场景**，解决了传统方法无法处理的上下文管理问题。通过向量数据库、语义检索和 Prompt 工程的有机结合，实现了：

- **可扩展性**：支持百万字级别的长篇小说创作
- **一致性**：确保长期创作中的设定和情节一致性
- **效率性**：大幅降低 Token 使用和生成成本
- **可控性**：通过 Prompt 工程精确控制生成内容

## 📝 适用场景

- 网络小说作者：辅助创作长篇连载小说
- 内容创作者：需要长期保持内容一致性的创作场景
- AI 应用开发者：学习 RAG 技术在长文本生成中的应用
- 研究机构：研究上下文管理和记忆机制
