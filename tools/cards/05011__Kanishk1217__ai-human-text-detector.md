# AI vs Human Text Detection

Fine-tunes `roberta-base` to classify text as AI-generated or human-written, with an explainable Streamlit app that highlights *why* it made each call and shows the model's measured accuracy.

New LJ Institute of Engineering & Technology, Ahmedabad. CSE-AIML, Design Engineering (3150001).

Team: Shah Vansh, Kevadiya Khanjan, Ramani Jenil, Pansari Kanishk. Guide: Prof. Milan Bhadaliya.

## What it does

Given a piece of text, the model predicts human vs AI and returns a confidence score for each class. The app also:

- Highlights the words that pushed the model toward its decision, using Integrated Gradients (Captum).
- Shows the held-out test accuracy of the trained model.
- Handles long documents by splitting them into overlapping token windows and combining the per-window scores with a length weighting.

Label convention: `0 = AI-Generated`, `1 = Human-Written`.

## Data

`prepare_data.py` streams `dmitva/human_ai_generated_text` from Hugging Face, where each row pairs a human-written text with an AI-written one for the same instruction. Flattening the pairs gives a naturally balanced set of clean, well-formed prose. The script cleans, deduplicates, balances, and subsamples it (default 15,000 pairs), then writes `Dataset.csv` (`text,label_id`). The shipped model is trained on this.

It also writes `essays_test.csv` from `andythetechnerd03/AI-human-text` as an out-of-distribution probe only (not training data). See "Robustness and honest evaluation" for why that dataset is a cautionary benchmark, not a target.

This is a public substitute for the team's original SIH2025 `Dataset.csv`. To use the original instead, drop it in as `Dataset.csv` (columns `text` and `label_id`) and skip `prepare_data.py`.

## Run the whole pipeline

```bash
python prepare_data.py         # writes Dataset.csv
python train.py                # writes the model, metrics.json, and report plots
streamlit run app.py           # launches the frontend
```

Training runs on GPU (CUDA, with mixed precision) or Apple Silicon (MPS) automatically, and falls back to CPU. On an M-series Mac the default 3-epoch run takes roughly an hour.

To load a model from the Hugging Face Hub instead of the local directory:

```bash
MODEL_NAME=your-username/text_detection streamlit run app.py
```

## Training setup

- Dynamic padding (`DataCollatorWithPadding`) pads each batch to its own longest sequence instead of padding everything to 256 tokens, which cuts training time significantly.
- 3 epochs with early stopping and `load_best_model_at_end` keeps the best checkpoint by F1 and avoids overfitting.
- `compute_metrics` is wired into the `Trainer`, so `evaluate()` returns accuracy, precision, recall, and F1 in one call, saved to `metrics.json`.
- `id2label` / `label2id` are set on the model, so predictions read as `AI-Generated` / `Human-Written` rather than `LABEL_0` / `LABEL_1`.

## How the explanation works

For a given text the app computes Integrated Gradients attributions with respect to the predicted class, using the word embeddings as the layer and the pad token as the baseline. Subword tokens are merged back into words, and each word is shaded by how strongly it supported the prediction. This is an indicator of model reasoning, not a guarantee.

## Deployment

The trained model (~500MB) is not in the repo. It is published on the Hugging Face Hub at [Kanishk1217/ai-human-text-detector](https://huggingface.co/Kanishk1217/ai-human-text-detector) (public) and loaded at runtime; `detector.py` falls back to it automatically when no local model directory is present.

### Free: Streamlit Community Cloud (recommended)

1. Push this repo to GitHub.
2. Go to share.streamlit.io, sign in with GitHub, authorize the repo.
3. New app → this repo → branch `main` → main file `app.py` → Deploy.
4. No secrets needed. First build installs the deps and downloads the model (a few minutes), then it is live at a permanent URL.

Streamlit Community Cloud is free and has enough RAM for `roberta-base`. It runs the Streamlit UI (`app.py`); the custom FastAPI frontend (`serve.py` + `web/`) is for local use or a Docker host.

### Paid alternatives (Docker / FastAPI frontend)

Both of these can host `serve.py`, but neither is free for this workload:
- **Render:** use `render.yaml`. Needs the Standard instance (2GB) — the free/starter 512MB tiers OOM on PyTorch.
- **Hugging Face Spaces:** the included `Dockerfile` works, but Docker Spaces now require a paid PRO plan.

### Cloudflare

Point a domain at whichever host, proxied through Cloudflare for TLS + CDN. For a quick local demo of the FastAPI UI without any host, `cloudflared tunnel --url http://localhost:8000` gives a temporary public URL while your machine runs `python serve.py`.

### Re-publishing the model

If you retrain, push the new model to the Hub (needs a HF write token) and any host picks it up:

```bash
HF_TOKEN=hf_xxx python push_to_hub.py <username>/ai-human-text-detector
```

Override the model at runtime with the `MODEL_NAME` env var. `metrics.json` and `calibration.json` are committed so the app applies calibration without the model present.

## Robustness and honest evaluation

Results: **99.98% accuracy** on 5,000 held-out (unseen) dmitva pairs, and it generalizes to real casual human text (informal notes, chat, reddit-style posts classify correctly). Guards for real-world use:

- **Calibration:** probabilities are temperature-scaled (fitted on held-out logits). The fitted temperature was ~1.0, i.e. the model is already well-calibrated.
- **Uncertain band:** below 60% confidence the app says "Uncertain" instead of forcing a label.
- **Short-text gate:** inputs under 15 words are flagged as too short to judge reliably.

**A finding worth reporting.** We also tried diversifying training with a second dataset (`andythetechnerd03/AI-human-text`). It raised the score on that dataset's own test set to ~98% but *broke* real-world use: the model started calling all clean, well-punctuated human writing "AI". The cause is a preprocessing artifact - that dataset's human samples are lowercased and unpunctuated, so the model learned "clean text = AI" rather than a real signal. We therefore ship the dmitva-only model and keep the essays set only as a cautionary out-of-distribution probe (`essays_test.csv`, `python eval_ood.py <model> essays_test.csv`). Lesson: more data helped a metric but hurt reality because the added data had artifacts. Real-world detection of text from a brand-new generator is still harder than any single benchmark suggests.

## Limitations

- Accuracy drops on very short texts.
- It flags AI-generated text but cannot identify which tool produced it.
- Performance depends on the training data and degrades as new generation models appear, so periodic retraining is expected.
