# SlopSense

## Explainable AI-powered Low-Quality Content Detector

Detects repetitive, generic, low-information content using specialized NLP models and semantic analysis.

Instead of identifying whether content was generated by AI, SlopSense evaluates the quality and informational value of content and explains why it may be considered "slop" (low-quality, generic, buzzword-heavy).

---

## Problem Statement

The internet increasingly contains content that appears polished but contributes little meaningful information. Existing AI detectors attempt to determine authorship, which is unreliable and often misleading. This project focuses on a different problem:

Can we identify content that is repetitive, generic, vague, or low-value regardless of whether it was written by humans or AI?

---

## Features

- Detects buzzword-heavy content
- Identifies generic and vague language
- Analyzes content specificity and informativeness
- Provides detailed explanations for scoring
- Generates actionable improvement suggestions
- Supports batch processing
- RESTful API for integration
- Specialized Gemma-based model for accurate detection

## Usage

### Option 1: Direct Inference

```python
from inference_gemma import SlopSenseGemmaDetector

detector = SlopSenseGemmaDetector()

# Analyze single text
text = "In today's rapidly evolving landscape, innovation is essential for success."
result = detector.evaluate_content(text)
detector.print_analysis(result, verbose=True)

# Batch analysis
texts = ["text 1", "text 2", "text 3"]
results = detector.batch_analyze(texts)
```

### Option 2: FastAPI Server (Multiple Inference Modes)

Start the server:
```bash
# Activate virtual environment first
source venv/bin/activate
uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
```

The API supports three inference modes:

#### Local Inference (Default)
Uses the local Gemma model (no API key required):
```bash
curl -X POST "http://localhost:8000/analyze" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Your text here",
    "verbose": false,
    "inference_source": "local"
  }'
```

#### Gemini API Inference
Uses Google's Gemini API (requires GEMINI_API_KEY in .env):
```bash
curl -X POST "http://localhost:8000/analyze" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Your text here",
    "verbose": false,
    "inference_source": "gemini"
  }'
```

#### Rules-Based Analysis Only
Uses heuristic rules without ML inference (fastest):
```bash
curl -X POST "http://localhost:8000/analyze" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Your text here",
    "verbose": false,
    "rules_only": true
  }'
```

API endpoints:
- `POST /analyze` - Analyze single text (supports `inference_source`, `verbose`, `rules_only`)
- `POST /batch-analyze` - Analyze multiple texts (up to 10 per request)
- `GET /health` - Health check
- `GET /` - API information

### Option 3: React Web UI (Minimalist Monochrome)

To run the frontend React client, make sure your FastAPI backend is running on port 8000, then start the Vite development server:
```bash
cd frontend
npm run dev
```
Open [http://localhost:5173](http://localhost:5173) in your browser to interact with the detector.

### 4. Configure Environment Variables (Optional, for Gemini API)

Create a `.env` file in the project root to enable Gemini API inference:
```bash
GEMINI_API_KEY=your_api_key_here
ALLOWED_ORIGINS=http://localhost:5173,http://localhost:5174
```

To get a Gemini API key:
1. Go to [Google AI Studio](https://aistudio.google.com/app/apikeys)
2. Click "Create API Key"
3. Copy the key and add it to your `.env` file

## Configuration

### Model Loading

The detector automatically:
- Uses GPU if available (CUDA)
- Falls back to MPS (macOS Metal Performance Shaders) if available
- Falls back to CPU if GPU unavailable
- Uses float16 precision on GPU for efficiency
- Uses float32 precision on CPU

### Environment Variables

```env
# Required for Gemini API inference
GEMINI_API_KEY=your_gemini_api_key_here

# Optional: Configure allowed CORS origins
ALLOWED_ORIGINS=http://localhost:5173,http://localhost:5174
```

### Generation Parameters

- max_new_tokens: 10 (for binary classification: "ai_generated" or "human_written")
- temperature: 0.0 (for Gemini API) or 0.7 (for local model)
- top_p: 0.95 (nucleus sampling, local model)
- do_sample: false (deterministic for accurate classification)

### Detection Process

1. Input text is sent to the specialized Gemma model
2. Model analyzes content for quality indicators
3. Structured analysis is generated with:
   - Slop Score (0-100, where 0 is high quality, 100 is low quality)
   - Classification (HIGH_QUALITY or LOW_QUALITY)
   - Key issues identified
   - Detailed reasoning
   - Improvement suggestions

### Scoring Scale

| Score | Classification | Meaning |
|-------|-----------------|---------|
| 0-20  | HIGH_QUALITY | Specific, concrete, informative content |
| 21-40 | HIGH_QUALITY | Generally good with minor issues |
| 41-60 | MIXED | Some slop characteristics |
| 61-80 | LOW_QUALITY | Significant slop indicators |
| 81-100| LOW_QUALITY | Predominantly low-quality slop |

## What SlopSense Detects

### Slop Indicators (Negative)
- Buzzwords: revolutionary, cutting-edge, synergy, paradigm, disruptive, leverage
- Vague language: basically, essentially, kind of, sort of, I think
- Generic statements: "In today's rapidly evolving world..."
- No specificity: Lack of numbers, names, concrete examples
- Hedging: might, could, seem to, tend to
- Repetition: Repeated ideas in different words
- Corporate jargon: Hollow phrases, empty language

### Quality Indicators (Positive)
- Concrete data: Numbers, statistics, percentages
- Specific examples: Named entities, case studies, real instances
- Direct language: Clear, confident statements
- Technical depth: Detailed explanations, context
- Unique perspective: Original insights, novel approaches
- Evidence-based: Citations, references, sources

## API Documentation

### Request Format

```json
{
  "text": "Content to analyze",
  "verbose": false,
  "inference_source": "local",
  "rules_only": false
}
```

**Parameters:**
- `text` (string, required): The content to analyze (max 5000 characters)
- `verbose` (boolean, default: false): Include verbose output
- `inference_source` (string, default: "local"): Choose inference backend:
  - `"local"` - Use local Gemma model (no API key needed)
  - `"gemini"` - Use Google Gemini API (requires GEMINI_API_KEY)
  - `"rules_only"` - Use rules-based analysis only (fastest)
- `rules_only` (boolean, default: false): Force rules-based analysis (overrides inference_source)

### Response Format

```json
{
  "text": "Content to analyze",
  "slop_score": 78,
  "classification": "LOW_QUALITY",
  "key_issues": ["Excessive buzzwords", "Generic vague language"],
  "reasoning": "Explanation of the score...",
  "suggestions": ["Replace buzzwords...", "Add statistics..."],
  "raw_analysis": "ai_generated",
  "highlights": [
    {
      "start": 0,
      "end": 15,
      "word": "In today's",
      "type": "vague_language",
      "reason": "Generic temporal reference"
    }
  ],
  "stats": {
    "total_words": 12,
    "buzzword_count": 2,
    "vague_count": 3,
    "specificity_count": 0,
    "human_indicator_count": 0,
    "sentence_count": 1,
    "sentence_len_std": 0.0,
    "vocab_variety": 0.92,
    "sentence_lengths": [12]
  }
}
```

**Response Fields:**
- `slop_score` (0-100): Lower scores = higher quality, higher scores = lower quality
- `classification` (string): "HIGH_QUALITY", "MIXED", or "LOW_QUALITY"
- `highlights` (array): Specific phrases and words flagged with reasons
- `stats` (object): Detailed linguistic statistics

## Advanced Configuration: Using Gemini API for Inference

SlopSense supports multiple inference backends. While the local Gemma model works without any API keys, you can optionally use Google's Gemini API for inference.

### Why Use Gemini API?

- **No local model setup** - No need to download ~9GB model weights
- **Faster inference** - Use cloud resources instead of local GPU/CPU
- **Simpler deployment** - Run on servers without GPU support

### Setting Up Gemini API

#### Step 1: Get Your Gemini API Key

1. Visit [Google AI Studio](https://aistudio.google.com/app/apikeys)
2. Click **"Create API Key"**
3. Select your Google Cloud project
4. Copy the generated API key

#### Step 2: Add to Environment File

Create a `.env` file in the project root:

```env
GEMINI_API_KEY=your_api_key_here
ALLOWED_ORIGINS=http://localhost:5173,http://localhost:5174
```

**⚠️ Security:** Never commit `.env` to version control. Add to `.gitignore`:

```
.env
```

#### Step 3: Use Gemini API

**In API Requests:**
```bash
curl -X POST "http://localhost:8000/analyze" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Your text to analyze",
    "inference_source": "gemini"
  }'
```

**In React Web UI:**
- Start the backend with `GEMINI_API_KEY` in `.env`
- Select "Gemini API" from the inference dropdown

**In Python:**
```python
import httpx

response = httpx.post(
    "http://localhost:8000/analyze",
    json={
        "text": "Your content here",
        "inference_source": "gemini"
    }
)
print(response.json())
```

### API Key Troubleshooting

| Error | Solution |
|-------|----------|
| **"GEMINI_API_KEY not set"** | Add `GEMINI_API_KEY=your_key` to `.env` and restart backend |
| **"403 Forbidden"** | Key may be invalid or revoked; regenerate from [AI Studio](https://aistudio.google.com/app/apikeys) |
| **"Timeout"** | Gemini API may be slow or unreachable; try local inference instead |
| **"429 Too Many Requests"** | Rate limited; check your quota at [Google Cloud Console](https://console.cloud.google.com/) |

## Troubleshooting

### Local Model Issues

**Model Loading Fails**
- Ensure internet connection for downloading model weights
- Check disk space (requires ~9GB for full model)
- Verify HuggingFace hub access

**Out of Memory (OOM)**
- Use Gemini API instead: `"inference_source": "gemini"`
- Or use rules-only mode: `"rules_only": true`
- On CUDA, try restarting the backend to clear GPU memory

**Slow Performance on Local**
- Use GPU acceleration if available (check with `nvidia-smi`)
- Or switch to Gemini API for faster inference
- Or use rules-only mode for instant results

### API Issues

**Backend won't start**
- Ensure port 8000 is not in use: `lsof -i :8000`
- Check Python/PyTorch installation: `python -c "import torch; print(torch.cuda.is_available())"`

**Frontend can't connect to backend**
- Verify backend is running on `http://localhost:8000`
- Check CORS origins in `.env` match your frontend URL
- Try using `"http://0.0.0.0:8000"` instead of `"http://localhost:8000"`

**GEMINI_API_KEY errors**
- See [API Key Troubleshooting](#api-key-troubleshooting) section above
