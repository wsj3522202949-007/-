# JobShield

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

A dual-signal detector for fake/scam job postings and AI-generated job postings.

Most fraud detectors collapse "is this a scam" and "did an AI write this" into a
single score. JobShield deliberately keeps them separate: a posting can be a
scam written by a human, or a perfectly legitimate role drafted with the help
of an LLM. Conflating the two hides which risk the reader should actually
worry about. JobShield returns **two sub-scores** (fraud likelihood,
AI-generated likelihood) plus a combined risk score and a plain-language
explanation of which signal drove the flag.

## Problem statement

Job seekers are increasingly targeted by fraudulent postings (data-harvesting
scams, "ghost jobs" that never intend to hire), and a growing share of postings
— legitimate and fraudulent alike — are now drafted or fully generated by LLMs.
JobShield analyzes a posting's free text and structured fields and returns a
risk breakdown that keeps those two questions distinct.

## Architecture

```
                         ┌─────────────────────────┐
                         │   ml/  (training)       │
                         │  signal_a_fraud/        │  XGBoost + SHAP
                         │  signal_b_ai_generated/ │  GPT-2 features + LogReg
                         │  scoring.py             │  combination layer
                         │  artifacts/*.joblib     │  trained models
                         └───────────┬─────────────┘
                                     │ imported directly at inference time
                         ┌───────────▼─────────────┐
                         │   backend/  (FastAPI)   │
                         │  POST /analyze          │  runs both signals,
                         │  GET  /history          │  persists to SQLite/PG
                         └───────────┬─────────────┘
                                     │ REST (axios)
                         ┌───────────▼─────────────┐
                         │  frontend/ (React+Vite) │
                         │  Submit → Results →     │
                         │  Recent scans dashboard │
                         └─────────────────────────┘
```

`ml/` and `backend/` share one Python virtual environment (`ml/.venv`) because
the backend imports `ml/scoring.py` directly for inference — a second
multi-gigabyte torch/transformers install would be pure waste for local dev.

## Dataset & methodology

**No Kaggle account needed.** Both signals are trained on real data pulled
from public HuggingFace Hub dataset mirrors — no API keys, no manual
downloads.

### Signal A — fraud/scam classifier

- **Data:** [`gplsi/fake_job_postings_balanced_en`](https://huggingface.co/datasets/gplsi/fake_job_postings_balanced_en),
  a genuine mirror of the EMSCAD ("Real or Fake Job Postings") dataset — 1,732
  rows with the exact original EMSCAD schema (title, location, department,
  salary_range, company_profile, description, requirements, benefits,
  telecommuting, has_company_logo, has_questions, employment_type,
  required_experience, required_education, industry, function, fraudulent).
- **Features:** hand-engineered structural signals (salary present/plausible,
  company profile completeness, free-mail contact domains mined from the
  text, urgency language, upfront-payment/equipment-purchase language,
  telecommuting flag, an industry/function co-occurrence "mismatch" score
  fit on the training set) concatenated with `all-MiniLM-L6-v2`
  sentence-transformer embeddings of title+description+requirements.
- **Model:** XGBoost, threshold tuned to favor **recall on the fraud class**
  over raw accuracy — in fraud detection, missing a real scam costs a job
  seeker far more than an extra false alarm costs a reviewer.
- **Explainability:** SHAP (`TreeExplainer`), with the 384 embedding
  dimensions aggregated into one "semantic content" bucket for human-readable
  output (an individual embedding dimension means nothing on its own).

### Signal B — AI-generation detector

- **Data:** no large labeled "AI-written job posting" corpus exists publicly,
  so this is a **hybrid, explicitly-flagged construction**: 120 real
  GPT-generated postings from [`cmagganas/GenAI-job-postings-Dataset`](https://huggingface.co/datasets/cmagganas/GenAI-job-postings-Dataset)
  (HF Hub), topped up to 300 with template/pattern-based synthetic postings
  assembled from common LLM stylistic tics, versus 300 real human-written
  *legitimate* postings sampled from the EMSCAD data above.
- **Why templates instead of local GPT-2 generation:** GPT-2 (124M) is too
  weak to produce coherent structured job postings — its output would bias
  the "AI-generated" class toward incoherence rather than the
  fluent-but-generic style that's the actual real-world concern with modern
  LLM-written listings.
- **Features:** GPT-2 perplexity and sentence-level burstiness (log-likelihood
  variance across sentences), plus stylometrics — sentence-length variance,
  type-token ratio, bigram repetition rate, and a generic-corporate-phrase
  count ("fast-paced environment", "self-starter", "leverage", etc).
- **Model:** logistic regression, deliberately kept simple — with 8 features,
  the coefficients *are* the explanation, rather than a black-box network.
- **Simplification:** perplexity is computed as a single forward pass
  truncated to GPT-2's 1024-token window per sentence, not a sliding window
  over very long postings.

### Combination layer

`ml/scoring.py` merges both probabilities into one 0–100 risk score via a
probabilistic OR (`1 - (1-fraud) * (1-ai)`) — either signal alone being
strong is enough to flag a posting — alongside the two visible sub-scores and
a plain-language explanation naming whichever signal (or both) dominated.

## Known limitations (read before citing this in a capstone writeup)

- **Signal A's dataset is a class-balanced ~1.7k-row EMSCAD subset**, not the
  full ~17,880-row / ~4.8%-fraud corpus. It contains essentially all of
  EMSCAD's real fraud examples paired with an equal legit sample — the fraud
  examples are genuine, but real-world class imbalance isn't represented.
- **Signal B's AI-generated class is a hybrid** of real GenAI-mirror text and
  template-generated synthetic text, not large-scale genuine LLM output —
  see the honesty check above for how much this matters in practice.
- **The fraud model over-weights structural completeness, especially
  company-profile presence**, because in the real EMSCAD training data
  legitimate postings almost always have one filled in. A genuinely
  legitimate posting submitted with only a title and description (no company
  profile, industry, or salary) can score **90%+ on fraud risk** purely
  because those fields are empty — reproduced directly:
  `title="Senior Backend Engineer", description="We're hiring a Senior
  Backend Engineer..."` scores 96.8% fraud with "company profile length" and
  "company profile provided" as the top SHAP drivers. The frontend surfaces a
  tip about this; a production system would need better handling of sparse
  submissions (e.g. a distinct "insufficient information" state rather than
  defaulting to high risk).
- GPT-2 perplexity is a single truncated forward pass, not a sliding window.
- The in-memory rate limiter (`backend/app/rate_limit.py`) is a local-dev
  stub — it resets on restart and doesn't share state across replicas. In
  production, replace it with a Redis-backed limiter or gateway-level
  rate limiting.

## Project layout

```
ml/                     training pipeline (see Dataset & methodology above)
  signal_a_fraud/       structural + embedding features, XGBoost, SHAP
  signal_b_ai_generated/  GPT-2 + stylometric features, logistic regression
  scoring.py            combination layer used by both manual_test.py and the backend
  manual_test.py        curated legit/scam/AI-generated sanity check
  artifacts/            trained models, metrics.json, confusion matrices, SHAP plots
backend/                FastAPI app (POST /analyze, GET /history)
frontend/               React + Vite + TypeScript + Tailwind
```

## Setup

Requires Python 3.11 (system Python 3.14+ has wheel-compatibility issues with
some ML packages) and Node 20+.

### 1. ML pipeline (train once, or use the checked-in artifacts)

```bash
cd ml
python3.11 -m venv .venv
source .venv/bin/activate
pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu  # CPU-only; skip the huge CUDA deps
pip install -r requirements.txt

python signal_a_fraud/load_data.py
python signal_b_ai_generated/build_ai_dataset.py
python signal_a_fraud/train.py && python signal_a_fraud/evaluate.py
python signal_b_ai_generated/train.py && python signal_b_ai_generated/evaluate.py
python manual_test.py   # sanity check against curated examples
pytest tests/
```

Trained model artifacts are committed under `ml/artifacts/` (small — XGBoost
model is ~350KB, logistic regression ~4KB), so you can skip straight to the
backend without retraining.

### 2. Backend

```bash
cd backend
source ../ml/.venv/bin/activate   # same venv as ml/ — see Architecture above
pip install -r requirements.txt
cp .env.example .env
pytest tests/
uvicorn app.main:app --reload --port 8050
```

### 3. Frontend

```bash
cd frontend
npm install
cp .env.example .env   # set VITE_API_BASE_URL if the backend isn't on :8050
npm run dev -- --port 5195
```

Then open `http://localhost:5195`.

## API

- `POST /analyze` — body: `{title, description, ...optional structured fields}`.
  Returns the full risk breakdown (overall/fraud/AI scores, explanation, top
  SHAP-driven features per signal, highlighted red-flag phrases). Rate-limited
  (20/min/IP by default, see limitations above).
- `GET /history?limit=&offset=` — paginated list of past analyses.

## Testing

- `ml/tests/` — pytest for feature-extraction functions (16 cases).
- `backend/tests/` — pytest with FastAPI's `TestClient`, including real
  end-to-end checks that a scam posting scores high on fraud but low on
  AI-generation and vice versa (8 cases).
- Frontend was verified with a scripted Playwright pass (submit → results →
  history, light and dark mode) rather than automated tests, given project
  scope.
