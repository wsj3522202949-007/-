# 06_shuorenhua 原始框架摘要

> 用途：把 shuorenhua 的改写哲学、场景分级、误杀防护、回读两步法保留成原始对照；不直接当模板，而是作为《最强去AI味铁律.md》《改稿润色指令库.md》的上游依据。
> 来源说明：本地仓库路径为 `E:\小说\小说sill\shuorenhua-main\shuorenhua-main`；README 标注该项目为中文第一人称改写 skill，支持 Codex / Claude Code / Cursor / ChatGPT。

## 一、这个 skill 的核心哲学

- **先保护，再润色**：不动术语、数字、命令、代码、引用、人名、隐私、代词、转折关联词。
- **按平台决定改法**：`chat / status / docs / public-writing` 四类场景，修改深度不同。
- **不是查杀 AI 痕迹，而是让文字自然、有人味**。
- **保留专业判断、链接和关键词**。

## 二、场景分级与修改深度

| 场景 | 默认深度 | 默认策略 |
|------|----------|----------|
| `chat` | 轻 | 只显式润色对话，不改成正式文章 |
| `status` | 中 | 保留动作、状态、触发器和下一步 |
| `docs` | 中 | 全部显式重写，二次回读更保守 |
| `public-writing` | 重 | 全面润色，且按 Scene Pack 决定 |

## 三、Scene Packs：按平台决定改写重点

- `README` 第一屏要写清：这是给谁改、改什么、给谁用。
- `Release note` 要列“改了什么 + 校验和策略”，不写泛泛感想。
- `Forum post` 要兼顾观看和回复，不写长段套话。
- `Issue reply` 先确认问题，再写下一步，不做客服套话。

## 四、长文不缩减，按三层 scope 处理

| scope | 说明 | 适用场景 |
|-------|------|----------|
| `structural` | 自由合并并重排 | 说明文、公开长文 |
| `bounded` | 句式缩扩 + 可注释删（默认） | `public-writing` 长文 |
| `in-place` | 只替换口语，不删不增 | 状态、要求、保留全文 |

原则：
- 具体动作优先于抽象评价。
- 弱化主语和动补结构优先于强动作。
- 允许替换同义词，不硬凑同一结构。

## 五、误杀防护（网文尤其重要）

- 不能把“主角目标”改成“客套表达”。
- 不能把“爽点触发词”改成“客服确认语”。
- 不能把“对话节奏”改成“文档说明语气”。
- 专业术语、数字、命令、引用必须原地保留。
- 人名字、隐私、代词、转折关联词优先保护。

## 六、回读两步法

1. **保真回读**：确认术语、数字、命令、引用、人名、隐私、代词、转折关联词没被改坏。
2. **残留味回读**：确认还有没有 AI 套话、总结腔、表演腔、虚假主语。

回读纪律：
- 第二遍只做轻量修正，不做大改。
- 不把任何一句话改成第二遍才发现的完全不同意思。

## 八、网文可吸收点

- 网文改稿时默认用“中改”深度，只对明显的 AI 腔、套话、总结腔下手，不删剧情。
- 对白场景优先做“轻改”：只润语气，不改信息密度。
- 长文大修时先做 structural，再做 bounded，最后做 in-place。
- 回读时必须再过一遍“人名词、专业词、数字、命令、引用”是否还在原句。
- 任何把“主角动作”改成“虚主语”或“客服腔”的改法，都视为误杀，必须回滚。
