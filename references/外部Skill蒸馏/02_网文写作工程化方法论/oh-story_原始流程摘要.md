# 02_网文写作工程化方法论（oh-story_原始流程摘要）

> 用途：把 `oh-story-claudecode` 里最值得网文工程复用的部分抽出来，作为原始对照；不替代《网文写作最强SOP.md》，只负责保留上游 schema、触发条件、停靠点和字段约束。
> 来源说明：本地仓库路径为 `E:\小说\小说sill\oh-story-claudecode-main`（`[历史路径]`）；网络复核时上游 `story-long-write` 可访问，标题结构与本地一致。

## 一、上游 skill 的核心骨架

### 核心方法
- 先定情绪，再定故事
- 从验证过的模式出发，少从灵感起步
- 用模块组装，不要重新发明
- 只加载必需信息
- 契约与推进决策走权威参考文件

### 写作流程触发表
| 触发条件 | 执行流程 | 停靠点 |
|----------|----------|--------|
| 帮我开书 | Phase 1→2→3 | 默认停在首批 10 章细纲 |
| 写第 N 章 | Phase 4 单章写作 | 写完检查后停止 |
| 日更 / 续写 | 日更 workflow | 每批最多 3 章 |
| 修改第 X 章 / 回炉 | 大修 workflow | 修纲优先 |

### 强制停靠点
- 裸调用时只做项目状态诊断，不自动写正文
- 开书默认不自动写正文，除非用户同一句明确要求
- 单轮最多 3 章，超过先拆批
- 细纲缺失、章节号冲突、用户要求逐章确认时，才暂停

## 二、核心设定字段

上游要求核心设定至少包含：

- 书名、题材、平台、字数、目标读者
- 读者契约
- 主角高光 / 代理权
- 核心期待债
- 一句话梗概
- 主角设定：姓名、年龄、核心特质、金手指、弱点、核心动机
- 世界观骨架：时代、核心设定、力量体系、社会结构
- 核心冲突：主线矛盾、终极阻碍

本地最强版继承要求：
- 读者契约必须写成可交付快感，不能写成空泛标签
- 主角代理权拆成因果权 + 结算权
- 期待债必须分成开篇、前 30 章、每卷结尾三个兑现节点

## 三、全书体量工程化规则

### 阶段比例参考
- 开篇期：10%-15%
- 发展期：50%-60%
- 高潮期：20%-25%
- 收尾期：5%-10%

### 阶段公式字段
每阶段都要写：
- 核心任务
- 情绪基调
- 爽点密度
- 伏笔策略
- 冲突层级
- 阶段钩子
- 禁止提前释放

### 关键节点要求
- 按 1/4、中点、3/4 至少各锚定一个关键情节
- 小/中/大高潮位置必须显式写出
- 阶段钩子链必须连续：开篇→发展→高潮→收尾

## 四、卷纲工程化规则

- 每卷只能有 1 条主推线，允许多条战果线
- 每卷必须写：功能、阶段、卷契约、终局储备、正式情节循环、阶段边界、核心事件、起始状态→结束状态
- 终局储备不能提前打光：底牌、升级台阶、宿敌、终极真相按剩余档数逐卷释放
- 新卷若引入新角色/势力/设定，必须先补核心设定，再写卷纲

## 五、细纲工程化规则

### 每章必填字段
- 核心事件
- 字数目标
- 阶段位置
- 循环 ID/位置
- 目标情绪
- 主角目标/关键选择
- 章节定位
- 结构公式
- 章首钩子
- 爽点
- 禁止提前释放
- 内容概括：起因、发展、转折、高潮、结尾
- 情节安排：主线、辅线、事件线、任务卡点、感情线、逻辑线
- 人物关系和出场顺序
- 情节细化：密/疏点、字数预算、功能标签
- 结尾设定和钩子

### 细纲纪律
- 每章一个文件，不允许跳章
- 开书先交付前 10 章，写 5 章再滚动补 5-10 章
- 已进入正文的前 10 章锁定，未经确认不得修改
- 字数预算合计必须落在 `[章目标, 章目标×1.1]`
- 细纲缺失时禁止写正文

## 六、正文写作工程化规则

### 单章准备顺序
1. 读取上一章正文
2. 读取本章细纲和卷纲
3. 读取伏笔、角色、势力、设定
4. 读取对标节奏、情绪模块、文风、题材正文提示卡
5. 确认本章意图和细纲优先边界

### 细纲优先边界
- 正文只能展开细纲已有事件、人物、冲突、伏笔和结尾钩子
- 不得为了凑字新增主线、新角色、新反转
- 不得提前写后续章剧情
- 过渡动作只能服务于细纲已列情节点

### 写作技巧提醒
| 场景 | 工程要求 |
|------|----------|
| 开篇 500 字 | 必须有钩子，不能从天气/风景开始 |
| 对白 | 推进剧情或揭示性格，不能只凑字数 |
| 打斗 | 写策略和反转，不写流水账 |
| 日常 | 必须带人物互动和伏笔 |
| 任务卡点 | 必须卡出信息/关系/代价/选择/伏笔变化 |
| 爽点释放 | 铺垫充分、释放干脆 |
| 章尾 | 必须有让读者想翻下一页的东西 |

### 字数约束
- 高速推进 ≥ 2000 字
- 正常节奏 ≥ 3000 字
- 舒缓铺垫 ≥ 3000 字
- 高潮爆发 ≥ 2000 字
- 低于目标 90% 先补细纲，高于目标 110% 先压过场

### 正文元信息隔离
- 标题行以外不得出现“第X章、上章、前文、后文、伏笔、细纲、读者”
- 需要承接前文时，必须写成角色可感知的事件锚点或相对时间

### 章节维护
- 写完后即时更新伏笔、时间线、角色状态
- 新复用角色/势力自动建档
- 每完成 50 章或一卷结束，压缩上下文归档

## 七、质量检查工程化规则

### 装逼/打脸/揭露章
- 爽点出手前必须有可指认的危机/期待段落
- 在场配角必须写出差异化反应

### 高压/生死/悲痛场景
- 收紧对话声线
- 搞笑担当让位
- 信息型角色不当科普嘴
- 对白逐句承接对方情绪

### 章节定位与张弛
- 高压/推进章必须配齐钩子、爽点、悬念
- 低压/关系/修炼/信息整理章允许弱爽点，但必须有往下看的理由
- 相邻章不能情绪趋同
