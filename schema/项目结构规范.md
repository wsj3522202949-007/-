# 小说项目标准结构规范

> 本文件冻结 `projects/作品名/` 下的目录与文件结构。新建书必须复制骨架模板，已有书按映射表迁移。

---

## 一、标准结构（冻结）

```
projects/作品名/
├── README.md                 # 项目级 frontmatter + 摘要
├── STATUS.md                 # 进度数字，不要只写感受
├── framework.md              # 核心设定/一句话总纲
├── outline.md                # 总纲/分卷细纲
├── chapters/                 # 正文
│   ├── README.md             # 章节索引
│   ├── 第001章-标题.md
│   └── 第002章-标题.md
└── entities/                 # 知识实体
    ├── characters/           # 人物
    ├── settings/             # 设定
    ├── locations/            # 地点
    └── items/                # 道具
```

### 冻结规则

1. **根级只有 4 文件 + 2 目录**：README / STATUS / framework / outline + chapters/ + entities/。不得在项目根级新增文件。
2. **英文文件名**：framework.md / outline.md / chapters/ / entities/ 使用英文，保持机器可读、跨工具兼容。
3. **正文目录名 chapters/**：不再用「正文/」，统一英文。
4. **知识实体嵌套 entities/**：人物/设定/地点/道具 统一收进 entities/，用英文子目录名。
5. **章节命名保留中文**：`第NNN章-标题.md` 格式不变（这是内容层，中文可读性优先）。

## 二、各文件职责

### README.md — 项目门面

| 维度 | 规则 |
|---|---|
| 职责 | 项目级 frontmatter + 一句话摘要 + 核心信息表 + AI协作边界 |
| frontmatter | `type: project`，含 `genre` `platform` `pov` `chapters_planned` `chapters_written` |
| 正文内容 | ① 一句话梗概 ② 核心信息表（书名/题材/平台/字数/卷数）③ 三大冲突 ④ AI协作边界（原 AGENTS.md 精华）⑤ 文件导航表 |
| 禁止 | 不放进度数字（→STATUS）、不放细纲（→outline）、不放正文 |

### STATUS.md — 进度数字

| 维度 | 规则 |
|---|---|
| 职责 | 量化进度，不要只写感受 |
| 内容 | ① 阶段标记（构思/大纲/开篇/连载/完结）② 进度指标表 ③ 章节推进表（原写作进度.md）④ 下一步+卡点（原TODO.md） |
| 更新频率 | 每次写完一章或推进一个阶段时更新 |
| 禁止 | 不放设定（→framework）、不放方法论引用 |

### framework.md — 核心设定

| 维度 | 规则 |
|---|---|
| 职责 | 核心设定/一句话总纲/风格基线 |
| 内容 | ① 题材定位 ② 一句话设定+金手指 ③ 世界观/背景 ④ 人物骨架表 ⑤ 卖点包装 ⑥ 开篇切入点 ⑦ 风格基线（原风格校准文档.md精华）⑧ 项目专属写作铁律（原SKILL.md精华） |
| 禁止 | 不放分卷细纲（→outline）、不放进度（→STATUS） |

### outline.md — 总纲/分卷细纲

| 维度 | 规则 |
|---|---|
| 职责 | 全书结构：分卷总览 + 各卷细纲 + 伏笔追踪 |
| 内容 | ① 分卷总览表（原全书创作手册-贯穿总览.md）② 各卷细纲（原分卷细纲.md+第一卷细纲.md）③ 伏笔管理表（原伏笔管理表.md） |
| 禁止 | 不放正文、不放人物单页（→entities/） |

### chapters/ — 正文

| 维度 | 规则 |
|---|---|
| chapters/README.md | 章节索引：命名规范 + 章节列表表（章号/标题/字数/状态） |
| 章节文件 | `第NNN章-标题.md`，带 chapter 类型 frontmatter，`status: final` 或 `published` |
| 准入条件 | 只放**已校验、已过自检的最终稿**。草稿在 `drafts/projects/作品名/`，详见[正文生命周期规范](正文生命周期规范.md) |
| 机检 | 全部 ERROR 级：缺 frontmatter / 缺必填键 / 死链 = 阻断提交 |
| 禁止 | 不放草稿（→drafts/）、不放知识实体、不放归档旧版（→archive/） |

### entities/ — 知识实体

| 子目录 | 内容 | 命名 |
|---|---|---|
| `characters/` | 每个角色一页 | `角色名.md` |
| `settings/` | 每个设定一页 | `设定名.md` |
| `locations/` | 每个地点一页 | `地点名.md` |
| `items/` | 每个道具一页 | `道具名.md` |

> 知识实体用标准 markdown 链接互链，仅在本项目内链接（书与书隔离）。

## 四、迁移执行要点

### 4.1 合并优先级

合并多个文件时，按以下顺序处理（避免内容丢失）：

1. **outline.md**：全书创作手册 → 分卷细纲 → 第一卷细纲 → 伏笔管理表（依次追加）
2. **STATUS.md**：保留原进度数字 → 追加写作进度章节表 → 追加TODO下一步
3. **framework.md**：保留原框架 → 追加风格基线 → 追加项目铁律
4. **README.md**：保留核心信息 → 追加AI协作边界

### 4.2 链接重写

项目内链接随目录重命名而变化：

| 旧链接模式 | 新链接模式 |
|---|---|
| `[文本](正文/第001章.md)` | `[文本](chapters/第001章.md)` |
| `[文本](人物/陆远.md)` | `[文本](entities/characters/陆远.md)` |
| `[文本](设定/国产芯片.md)` | `[文本](entities/settings/国产芯片.md)` |
| `[文本](地点/电子城.md)` | `[文本](entities/locations/电子城.md)` |
| `[文本](道具/二手主板.md)` | `[文本](entities/items/二手主板.md)` |
| `[文本](框架.md)` | `[文本](framework.md)` |
| `[文本](分卷细纲.md)` | `[文本](outline.md)` |

### 4.3 frontmatter 更新

| 旧字段 | 新字段 | 说明 |
|---|---|---|
| 无变化 | — | frontmatter 字段名不变，但 `area` 值可能需调整 |
| `area: 项目` | `area: projects` | 随目录冻结同步 |

## 五、与 vault 顶层结构的关系

```
vault/
├── projects/                          ← 本规范管辖范围
│   ├── <你的书名>/                     ← 每本书遵循本规范
│   │   ├── README.md
│   │   ├── STATUS.md
│   │   ├── framework.md
│   │   ├── outline.md
│   │   ├── chapters/
│   │   └── entities/
│   └── <另一本书>/
├── methods/                           ← 项目共享的方法论
│   ├── 项目骨架模板/                  ← 本规范的骨架模板
│   └── templates/                     ← 作战卡等通用模板（原模板应用/）
└── ...
```

> 项目内不存放通用方法论——通用内容在 `methods/`，项目只存「这一本书」的专属内容。
