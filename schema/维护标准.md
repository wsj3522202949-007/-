# 🛡️ 知识库维护标准（不变量契约 + 维护仪式）

> 本文件是知识库的「宪法」。它把前面几轮沉淀的约定**固化成可机检的不变量**，并给出**维护仪式**，让库「越用越不乱」。
> 配套的机检工具：[tools/scripts/validation/校验脚本.py](../tools/scripts/validation/校验脚本.py)（跑一次 30 秒，提交前必跑）；运行记录：[维护日志](../archive/规范归档/维护日志.md)。

> 📌 **本文件范围**：原《维护标准》曾承载 8 项职责，现已按「一个文件一个职责」拆为四份。本文件只保留**不变量契约（§一）**与**维护仪式（§三）**两项核心契约；五层架构蓝图见 [五层结构蓝图.md](../archive/规范归档/五层结构蓝图.md)，目录与命名守则见 [目录与命名规范.md](目录与命名规范.md)，排错与禁忌见 [排错与禁忌.md](../archive/规范归档/排错与禁忌.md)。

## 〇、为什么需要维护机制

知识库会自然熵增：手改 frontmatter 打错标签、新增笔记忘打 `area/`、wiki 链接指向已改名文件、工具卡标签混入命名空间……单靠人记不住。本机制用三条防线兜底：

1. **定标准**（本文 + [标签规范](../tools/标签规范.md)）：什么是合法的。
2. **写校验脚本**（[tools/scripts/validation/校验脚本.py](../tools/scripts/validation/校验脚本.py)）：机器守门，ERROR 阻断提交。
3. **留维护文档**（本文 + [维护日志](../archive/规范归档/维护日志.md)）：仪式与排错有据可查。

## 一、不变量契约（机检项，ERROR = 不可提交）

以下任何一条被打破，校验脚本报 ERROR，提交前应修复。

### 1.1 工具卡（`../tools/cards/*.md`）
| 不变量 | 含义 |
|---|---|
| 四字段齐全 | `tier` `tags` `use_case` `pitfalls`（+ `stars`） |
| `tier` ∈ {S, A, B, C} | 分层法定 |
| `tags` 每项是「受控词(17)」或「技术语言(ASCII)」 | 受控词见 [标签规范](../tools/标签规范.md) §一；其余视为实现语言 |
| 工具卡 `tags` **禁止**含 `/` | 命名空间标签只能出现在笔记层，两套靠 `/` 区分 |
| 中文且非受控的标签 = ERROR | 领域信息应留 `category`，不得泄漏进 `tags` |
| `use_case` 非空 | 使用场景必填 |

### 1.2 笔记层（带 frontmatter 的非工具卡笔记）

> **权威 schema 见 [frontmatter规范.md](frontmatter规范.md)**。以下为机检要点的摘要；旧命名空间标签格式（`tags: [type/xxx, area/xxx]`）过渡期保留为 WARN，迁移完成后升级为 ERROR。

| 不变量 | 含义 |
|---|---|
| **新格式**：平键 `type` `area` `status` 为独立 YAML 键 | 取值受控，非法值 = ERROR |
| **旧格式**：`tags` 含 `type/ area/ status/` 命名空间标签 | 过渡期 WARN（不阻断），建议迁移为平键 |
| `area` ∈ {库, 方法, 项目, 资料, 日记, 索引} | 扩展为全库 6 区 |
| `type` ∈ {index, guide, ref, dashboard, template, moc, demo, project, chapter, character, setting, location, prop, tool, daily-note, book-note} | 新增 tool/daily-note/book-note |
| `status` ∈ {active, demo, wip, done, draft, archived} | 新增 draft/archived |
| 通用字段（id/title/summary/created/updated） | 过渡期 WARN（[G] 检查），迁移完成后升 ERROR |

### 1.3 结构不变量
| 不变量 | 含义 |
|---|---|
| `../tools/分类导航/*.md` 每篇含 `type: moc`（平键）或 `type/moc`（旧标签，WARN） | MOC 识别键 |
| readme 命名 `^\d{5}__<owner>__<repo>\.md$` | 索引前缀 + 双下划线分隔（见 [排错与禁忌.md](../archive/规范归档/排错与禁忌.md) §已知例外） |
| tier 分布合计 == readme 总数 | 计数自洽 |

### 1.4 关键链接
| 不变量 | 含义 |
|---|---|
| [选型指南](../tools/工具选型指南.md) 与 [仪表盘](../tools/仪表盘.md) 中 `../tools/cards/...` 目标存在 | 工具卡指针不失效（markdown 链接 + 残留 wikilink 均检查） |

> **WARN（不阻断）**：readme 命名不规范（当前 37 个历史遗留名，见 [排错与禁忌.md](../archive/规范归档/排错与禁忌.md) §已知例外）、`use_case` 为空。这些是已知噪声，不阻断提交但应在维护日志备注。

### 1.5 命名契约（E 类机检，ERROR 阻断）

这四条是「多书 vault 不串味、点啥都不崩、写时不用想结构」的命名底线，由 `tools/scripts/validation/校验脚本.py` 的 **[E] 命名契约 / [B] 标签 / [F] 正文 frontmatter** 自动门禁（ERROR=0 才放行提交）。

| 编号 | 契约 | 机检行为（校验脚本 [E]/[B]/[F]） |
|---|---|---|
| ① 正文命名 | `正文/` 下（README.md 除外）每章固定 `第NNN章-标题.md`（零填充 3 位，如 `第001章-汇报会上的新甲方.md`）；不合并多章、不另起名 | 非 `第\d{3}章-*.md` 即 `[E1] ERROR`；范围限 `projects/`，`archive/` 原始来源包豁免 |
| ② 知识单页位置 | `人物/` `设定/` `地点/` `道具/` **只在项目目录内**（`projects/<书名>/人物/...`），**不得下沉到 vault 根** | 在 vault 根出现即 `[E2] ERROR` |
| ③ 标签纯度 | `tags` 只放纯关键词标签（`type/area/status` 写独立平键，`platform/genre/pov/chapter/kind` 也写独立 YAML 键） | 旧格式 `tags: [type/xxx]` 过渡期 WARN；新格式 `tags` 含 `type/ area/ status/` 命名空间标签即 `[B] WARN`（建议清理） |
| ④ 正文 frontmatter 强制 | `正文/第NNN章-*.md`（README.md 除外）**必须**带 frontmatter，含必填键 `title` `chapter` `status` `type`，且 `type`=`chapter`（平键）或 `type/chapter`（旧格式 WARN）、`chapter` 数值与文件名 `第NNN章` 序号一致 | 缺 frontmatter / 缺键 / `type` 错 / `chapter` 与文件名不符 → 均 `[F] ERROR`；旧格式 `type/chapter` → `[F] WARN`；范围限 `projects/`，`archive/` 豁免 | 命名契约与[五层结构蓝图](../archive/规范归档/五层结构蓝图.md)互为表里：① 锁 L2 正文层命名、② 锁 L2 知识单页层不越层、③ 锁 `tags` 纯度、④ 锁 L2 正文层 frontmatter。违反任一条 → 提交被 pre-commit 钩子阻断。

## 三、维护仪式（何时跑校验）

| 时机 | 动作 | 阻断？ |
|---|---|---|
| **每次提交前**（动到 `../tools/` 或任何带 frontmatter 笔记） | 跑 `tools/scripts/validation/校验脚本.py`，ERROR=0 再提交 | ERROR 阻断 |
| **新增工具仓库后** | 跑 `_enrich_readmes.py` 富集 → 跑校验 → 提交 | ERROR 阻断 |
| **每周（或每月）例行** | 跑校验 → 把结论追加进 [维护日志](../archive/规范归档/维护日志.md) | 记录即可 |
| **重装 Obsidian / 换机后** | 装 Dataview 插件 + 确认 `小说工作台.css` 已启用 | — |
| **动到 `../tools/` 工具卡 / 更新标签 / 想刷新统计** | 跑 `python _仪表盘_快照.py` 重生成 `仪表盘-静态版.md`（零依赖快照） | 不阻断，滞后仅影响可读性 |

### 三·一、持续维护节奏（写作期日常仪式）

> 以下四条是「边写边养库」的最小动作清单。每条都是**在你完成某件事之后顺手做**，不是额外负担。
> 前三条是**动作触发联动**（你写了章 / 加了人 / 收了坑 → 我联动补周边）；第四条是**日历周期任务**（每季度一次，已建自动巡检，见 §三·一末尾）。

| 触发动作 | 顺手做的维护动作 | 门禁 |
|---|---|---|
| **每写完一章** | ① 更新该章 `正文/第NNN章-*.md` 的 frontmatter：`status` 由 `wip`→`done`、如有 POV 变化改 `pov`；② 刷新 `写作进度.md` 的「当前在写 / 下一步」行 + 项目 README 顶部「📍5秒仪表盘」进度；③ 跑双门禁（`tools/scripts/validation/校验脚本.py` 须 PASS + `链接体检与修复.py --fix`） | 校验 ERROR=0 才交卷 |
| **每新增一个人物 / 设定 / 地点 / 道具** | ① 在对应目录建单页（`人物/设定/地点/道具/新名.md`），补 frontmatter：`type:(character/setting/location/prop)` + `area: 项目` + `status: active`（+ `related`/`pov` 可选键）；② 用标准 markdown 链接 `[新名](projects/书名/对应目录/新名.md)` 互链；③ 更新对应 MOC（人物进 `人物设定卡.md` 链接栏；设定/地点/道具 在各自目录内自洽，若已建 MOC 则同步）；④ 已写正文章节反向链该单页，织成双向网 | 建页即带 frontmatter；[B] 查平键取值，[F] 不查单页 |
| **每回收一个伏笔** | ① 在 `伏笔管理表.md` 把对应 `F-xxx` 状态由「待回收 / 进行」改为「已收」，填回收章节；② 在相关正文章节（`正文/第NNN章-*.md`）加回链 `[伏笔F-xxx](projects/书名/伏笔管理表.md)`（或链到被回收实体单页），形成正文↔线索闭环 | 回链用 markdown 相对路径，链接体检须 0 失效 |
| **每季度整理一次** | 巡检 `archive/`：列出低价值素材（临时日志 `_*.txt` / pyc 缓存 / `*scratch*` / 空文件 / 重复稿），清理或重命名；保留有溯源价值的原始调研。处理完跑双门禁确认不破链 | 已建自动巡检（见下） |

> **每季度自动巡检**：已用 automation 建「季度知识库整理」任务（`FREQ=MONTHLY;INTERVAL=3`，每 3 个月触发），到期会提醒执行上表第四条。巡检**只报告、不自动删**，清理 / 重命名须经你确认后再做。

**如何跑**
```bash
# 仓库根目录下
python tools/scripts/validation/校验脚本.py            # 人类可读报告
python tools/scripts/validation/校验脚本.py --json     # 机器可读（可接 CI）
```
> 用本机托管 Python：`C:/Users/wsj/.workbuddy/binaries/python/versions/3.13.12/python.exe tools/scripts/validation/校验脚本.py`

**退出码**：`0` = 无 ERROR（可提交）；`1` = 有 ERROR（先修）。WARN 不阻断。

### pre-commit 钩子（已安装 · 提交前自动门禁）
本仓库已安装 `.git/hooks/pre-commit`，提交前自动机检，**已生效**：
- **不变量契约（校验脚本）ERROR → 阻断提交**（退出码 1）。必须修复 ERROR 才能提交；WARN 不阻断。
- **链接体检 → 仅报告不阻断**。

> 临时跳过机检：`git commit --no-verify`（不推荐，仅紧急用）。
> 迁移/重装：把下方内容存为 `.git/hooks/pre-commit` 并 `chmod +x`（注意先 `sed -i 's/\r$//'` 清 CRLF，否则 sh 解析报错）。

```sh
#!/bin/sh
ROOT="$(git rev-parse --show-toplevel)"
cd "$ROOT" || exit 1
DEF_PY="C:/Users/wsj/.workbuddy/binaries/python/versions/3.13.12/python.exe"
if [ -n "$PYTHON_BIN" ]; then
  PY="$PYTHON_BIN"
elif [ -x "$DEF_PY" ]; then
  PY="$DEF_PY"
elif command -v python >/dev/null 2>&1; then
  PY=python
elif command -v python3 >/dev/null 2>&1; then
  PY=python3
else
  echo "⚠️ [维护机制] 未找到 Python，跳过机检（提交未阻断）。请安装 Python 或设置 PYTHON_BIN 后重跑。"
  exit 0
fi
echo "🛡️ [维护机制] 提交前机检 — 不变量契约"
"$PY" tools/scripts/validation/校验脚本.py
RC=$?
if [ "$RC" -ne 0 ]; then
  echo "❌ 校验脚本报 ERROR（退出码 $RC），提交已阻断。修复后重新 git add + git commit；确需跳过用 git commit --no-verify"
  exit 1
fi
echo "✅ 不变量契约 PASS（ERROR=0）"
echo "🔗 [维护机制] 链接体检（仅报告，不阻断）"
"$PY" "../methods/工具/链接体检与修复.py" || true
exit 0
```
