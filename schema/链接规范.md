## 一、为什么废除 wikilink 作为唯一引用

Obsidian 的 `[[wikilink|alias]]` 语法是 Obsidian 专属扩展，标准 markdown 不识别。这导致：

1. **AI/RAG 管道无法稳定消费**：`[[path/file|alias]]` 不是标准 markdown，多数解析器（markdown-it、CommonMark、Python markdown）会把它当纯文本，丢失链接关系。
2. **跨工具迁移受限**：导出到 GitLab/GitHub Wiki、Notion、Confluence 等平台时，wikilink 全部失效。
3. **结构信息不可机读**：文档间的关联关系藏在正文 wikilink 里，无法用 frontmatter 字段查询。

## 二、三种引用方式（按优先级排列）

### 2.1 标准 markdown 链接（首选，正文引用）

```markdown
[显示文本](相对路径/文件.md)
```

- 用于正文中的文档间引用（"见：`[结构学](../craft/结构学.md)`"）
- 路径为**相对于当前文件的相对路径**（不是 vault 根路径）
- 任何 markdown 解析器都能识别

**转换规则**：

| 旧 wikilink | 新 markdown 链接 |
|---|---|
| `[[库/工具选型指南\|工具选型指南]]`（从 `../methods/` 引用） | `[工具选型指南](../tools/工具选型指南.md)` |
| `[[README\|🗺️ 知识库总地图]]`（从子目录引用） | `[🗺️ 知识库总地图](../README.md)` |
| `[[craft/结构学]]`（无别名） | `[结构学](../craft/结构学.md)`（示例，目标目录待建） |
| `[[README]]`（短名） | 需解析路径后转为相对路径 |

### 2.2 frontmatter `related` 字段（结构化关联）

```yaml
---
related:
  - craft/结构学.md
  - craft/大纲工程.md
  - 模板库.md
---
```

- 用于声明**本文件与哪些文件有结构性关联**（不是正文引用，是知识图谱边）
- 路径为 **vault 根相对路径**（不是文件相对路径），便于全局查询
- 值为文件路径列表，不含别名
- AI/RAG 可直接解析为图结构的邻接表

### 2.3 frontmatter `see_also` 字段（扩展阅读）

```yaml
---
see_also:
  - craft/卡文急救.md
  - craft/节奏与留白.md
---
```

- 用于声明**"如果你想深入了解，还可以看这些"**的扩展阅读推荐
- 与 `related` 的区别：`related` 是强关联（同体系），`see_also` 是弱关联（扩展阅读）
- 路径同样为 vault 根相对路径

### 2.4 Obsidian wikilink（兼容保留，不作为主结构）

`[[wikilink|alias]]` 语法**允许保留**，但：

- **不作为唯一引用方式**——关键引用必须有 markdown 链接或 frontmatter 字段兜底
- **不用于结构化关联**——文档间关联关系用 `related`/`see_also`，不用 wikilink
- **仅用于 Obsidian 内的便利跳转**——如果文档已有 markdown 链接，不再额外加 wikilink

> **过渡策略**：现有 wikilink 通过转换脚本批量转为 markdown 链接。转换后 wikilink 保留与否取决于是否需要 Obsidian 双向链接面板——如不需要，可彻底删除。

## 三、使用场景对照表

| 场景 | 用什么 | 示例 |
|---|---|---|
| 正文中提到另一篇文档 | markdown 链接 | `见 [结构学](../craft/结构学.md)` |
| 文档顶部"回总地图"导航 | markdown 链接 | `&#91;🗺️ 回总地图&#93;(../README.md)` |
| 声明本文件的结构性关联 | frontmatter `related` | `related: [craft/结构学.md, craft/大纲工程.md]` |
| 声明扩展阅读推荐 | frontmatter `see_also` | `see_also: [craft/卡文急救.md]` |
| 工具卡之间的分类导航 | markdown 链接 | `&#91;storyteller&#93;(../tools/cards/00007__FaceDeer__storyteller.md)` |
| 人物/设定之间的互链 | frontmatter `related` | `related: [人物/陆远.md, 设定/超脑能力.md]` |
| 仪表盘 Dataview 查询 | wikilink（Obsidian 专属，保留） | Dataview 查询语句中的 `[[...]]` 保留 |
| 代码块/教程中的字面量 | 不转换 | 教学示例：`` &#91;&#91;wikilink&#93;&#93; `` 不转换 |

## 四、路径规范

### 4.1 markdown 链接路径

- **相对于当前文件所在目录**计算
- 用 `/` 分隔（Windows 也用正斜杠，markdown 标准）
- 包含 `.md` 扩展名
- 示例：从 `../methods/导览.md` 引用 `../tools/工具选型指南.md` → `../tools/工具选型指南.md`

### 4.2 frontmatter related/see_also 路径

- **相对于 vault 根**计算
- 包含 `.md` 扩展名
- 示例：`related: [craft/结构学.md, craft/大纲工程.md]`

> 两种路径基准不同：markdown 链接用文件相对路径（可移植性好），frontmatter 用 vault 根相对路径（全局查询方便）。

## 五、迁移策略

### 5.1 批量转换（脚本化）

转换脚本 `tools/scripts/validation/wikilink_to_md.py` 负责：

1. 扫描全库 `.md` 文件（排除 archive/、.git/、.workbuddy/、代码块内字面量）
2. 匹配 `` &#91;&#91;target|alias&#93;&#93; `` 和 `` &#91;&#91;target&#93;&#93; `` 两种模式
3. 解析 target 为实际文件路径（vault 根相对）
4. 计算从当前文件到目标文件的相对路径
5. 替换为 `&#91;alias&#93;(相对路径.md)` 或 `&#91;文件名&#93;(相对路径.md)`
6. 跳过：代码块内、Dataview 查询块内、无法解析的短名

### 5.2 转换优先级

| 目录 | wikilink 数量 | 优先级 | 原因 |
|---|---|---|---|
| `../methods/` | 62 | P0 先转 | 方法论核心，AI/RAG 消费最频繁 |
| `维护/` | 37 | P0 先转 | 维护文档，机检依赖 |
| `projects/` | 188 | P1 | 项目内部互链 |
| `../tools/` | 7662 | P2 后转 | 数量大，多为 MOC/选型指南自动生成 |
| `仪表盘*.md` | 545 | P3 最后 | Dataview 专属，部分需保留 wikilink |

### 5.3 不转换的情况

- **Dataview 查询块**内的 `[[...]]`（Obsidian 插件语法，不是文档引用）
- **代码块**内的字面 `[[...]]`（教学示例）
- **frontmatter** 内的 `[[...]]`（如果有的话，应改为路径字符串）
- **仪表盘.md** 中 Dataview 查询使用的 wikilink（保留给 Obsidian）
