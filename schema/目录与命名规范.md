# 📁 目录与命名规范（人工守则）

> 本文件从原《维护标准》拆出，专司目录结构与命名约定——给人看的硬规则，区别于 [维护标准.md](维护标准.md) 里给机器检的不变量契约。
> 架构层级的定义见 [五层结构蓝图.md](五层结构蓝图.md)。

---

## 二、目录与命名规范（人工守则）

```
vault/
├─ README.md                 唯一前门（总地图 + 速查 + 结构说明）
├─ schema/                   规范与契约（frontmatter/链接/命名/维护标准）
├─ projects/                 所有项目（小说/非小说统一）
│  └─ 作品名/
│     ├─ README.md             L1 项目门面
│     ├─ STATUS.md             进度数字
│     ├─ framework.md          核心设定 + 风格校准 + 写作铁律
│     ├─ outline.md            总览 + 分卷细纲 + 伏笔管理
│     ├─ chapters/             L2 正文层（第NNN章-标题.md）
│     └─ entities/             L2 知识单页层
│        ├─ characters/        人物
│        ├─ settings/          设定
│        ├─ locations/         地点
│        └─ items/             道具
├─ knowledge/                结构化知识实体（craft/genres/platforms/中国网文）
├─ drafts/                   写作中草稿（inbox/journal/projects/scratch）
├─ archive/                  归档（不再迭代、只保留不删除）
├─ references/               参考资料与外部素材（方法论素材/Skill蒸馏/在线调研）
├─ methods/                  可复用方法论（SOP/铁律/模板库/自检清单/骨架模板）
└─ tools/                    工具说明与脚本
   ├─ cards/                 3574 篇工具情报卡
   ├─ 分类导航/              21 个分类 MOC
   └─ scripts/               校验/维护/写作脚本
```

**硬规则**
1. 新增工具卡 → 走 `_enrich_readmes.py` 自动生成，**不手改 frontmatter 四字段**（除重跑脚本）。
2. 新增笔记 → 必加 `type/ area/`（`status/` 可选），取值**只**从 [维护标准.md](维护标准.md) §1.2 表取。
3. 跨目录链接用标准 markdown 链接（相对路径），回前门用 `[🗺️ 知识库总地图](../README.md)`。链接引用方式详见 [链接规范.md](链接规范.md)。
4. 临时/脚本类 `.py` 以 `_` 开头（`_*.py`），已 gitignore + Obsidian 忽略，不入版本、不污染 vault。
5. 维护机制本身文件（`tools/scripts/validation/校验脚本.py`）**不带 `_` 前缀**，需版本化。
6. **入口命名约定（导航纪律）**——全库只能有一个前门，其余都是子地图：
   - **唯一前门 = `README.md`（总地图）**。新增内容**不要**另建"入口/地图/总览/导航"文件，挂到对应区的 L1/L2 即可。
   - **五大区入口文件名固定**：工具库 = `../tools/README.md`、方法论 = `../methods/导览.md`、参考资料 = `../references/README.md`、项目 = `../projects/*/README.md`、维护 = `维护标准.md`（本目录）。改名须同步 `README.md` 总图与所有 `↩ 回总地图` 链接。
   - **每个子地图顶部必须有 `↩ 回总地图`** 链接（`[🗺️ 知识库总地图](../README.md)`），迷路一键回前门。
   - 链接体检脚本已跳过代码块且 `README` 始终存在，子地图内的 `↩` 不会被误判断链；新增区入口请确保其可被 vault 解析。
