# 知识库宪法（统一规范）

> 本文件是知识库的**最高宪法**，统一解决所有规范冲突。当其他规范与本文件冲突时，**以本文件为准**。
> 配套执行文档见 [README.md](README.md) 和各专项规范。

## 一、顶层目录结构（9目录冻结）

### 1.1 目录清单（已冻结）

| 目录 | 职责（一句话） | 当前内容 | 禁止放入 |
|---|---|---|---|
| `schema/` | 规范与契约 | 6 个核心规范文件 | 脚本、正文、工具卡 |
| `projects/` | 所有项目 | 当前 3 个项目 | 方法论、工具卡、草稿（→drafts/） |
| `knowledge/` | 结构化知识实体 | craft/ 20篇 · genres/ 29篇 · platforms/ 8篇 · 中国网文/ 4篇 | 可执行 SOP、模板、工具卡 |
| `drafts/` | 写作中草稿 | inbox/ journal/ projects/ scratch/ | 已校验最终稿、归档 |
| `archive/` | 归档 | 项目骨架模板-旧版/ + 规范归档/ | 活跃项目内容、常用参考资料 |
| `references/` | 参考资料与外部素材 | 49 篇指南 + Skill 蒸馏 + 原始调研 + 原始来源包 | 自创的方法论、项目正文 |
| `methods/` | 可复用的方法论 | 18 篇 + templates/ 15 篇 + 项目骨架模板/ | 知识实体、工具卡 |
| `tools/` | 工具说明、选型与脚本 | cards/ 348 卡 + 分类导航/ 21 MOC + scripts/ | 方法论正文、项目正文 |
| `goals/` | 目标级联系统 | 愿景 → 年度 → 月度 → 周 → 日 | 临时笔记、具体任务细节 |

### 1.2 目录职责详解

#### schema/ — 规范与契约
- **定位**：全库最高规范，机器可读的契约文件
- **内容**：6 份核心规范（本文件 + frontmatter + 目录命名 + 项目结构 + 链接 + AI协作）
- **变更**：冻结，不得随意修改
- **入口**：[schema/README.md](README.md)（待创建）

#### projects/ — 所有项目
- **定位**：小说项目统一存放处
- **结构**：每个项目遵循 [项目结构规范](项目结构规范.md)
- **命名**：`projects/作品名/`
- **状态**：以项目根级 `STATUS.md` 为准

#### knowledge/ — 结构化知识实体
- **定位**：AI 可读的结构化知识库
- **子目录**：
  - `craft/` — 写作技艺（结构学、人物学、节奏学等）
  - `genres/` — 题材分类（仙侠、都市、科幻等 29 个题材）
  - `platforms/` — 平台规则（番茄、起点、晋江等 8 个平台）
  - `中国网文/` — 行业分析（市场、变现、趋势等）
- **内容**：纯知识实体，不含可执行内容

#### drafts/ — 写作中草稿
- **定位**：未完成内容的暂存区
- **子目录**：
  - `inbox/` — 收件箱，未分类内容
  - `journal/` — 日记/反思
  - `projects/` — 项目草稿（按项目分）
  - `scratch/` — 临时草稿
- **生命周期**：草稿 → 校验 → 进入 projects/

#### archive/ — 归档
- **定位**：不再迭代、只保留不删除
- **子目录**：
  - `规范归档/` — 历史规范文档
  - `项目骨架模板-旧版/` — 旧版项目模板
- **原则**：保留原始状态，不修改、不删除

#### references/ — 参考资料与外部素材
- **定位**：外部参考资料存放处
- **子目录**：
  - `在线调研/` — 网页快照和调研数据
  - `外部Skill蒸馏/` — 外部 Skill 的精华摘要
- **原则**：外部资料，非原创方法论

#### methods/ — 可复用的方法论
- **定位**：原创的可复用写作方法论
- **内容**：
  - 18 篇核心方法论文档
  - `templates/` — 15+ 作战卡模板
  - `项目骨架模板/` — 新建项目的骨架
- **区分**：原创方法论 vs 参考资料（references/）

#### tools/ — 工具说明、选型与脚本
- **定位**：AI 写作工具情报网
- **内容**：
  - `cards/` — 3572 篇工具情报卡（**实际数量**）
  - `分类导航/` — 21 个分类 MOC
  - `scripts/` — 校验/维护/写作脚本
- **工具卡数量**：**3572 篇**（以实际文件数为准）

#### goals/ — 目标级联系统
- **定位**：从愿景到日任务的目标管理
- **结构**：
  ```
  goals/
  ├── vision.md          # 3年愿景
  ├── yearly/            # 年度目标
  ├── monthly/           # 月度目标
  ├── weekly/            # 周回顾
  ├── daily/             # 日任务
  ├── GUIDE.md           # 使用指南
  └── README.md          # 目标系统说明
  ```
- **原则**：目标驱动，内容可追溯

## 二、项目结构规范（统一版）

### 2.1 标准结构（已冻结）

```
projects/作品名/
├── README.md                 # 项目门面
├── STATUS.md                 # 进度数字
├── framework.md              # 核心设定
├── outline.md                # 总纲/分卷细纲
├── chapters/                 # 正文（英文目录名）
│   ├── README.md             # 章节索引
│   ├── 第001章-标题.md
│   └── 第002章-标题.md
└── entities/                 # 知识实体（英文目录名）
    ├── characters/           # 人物
    ├── settings/             # 设定
    ├── locations/            # 地点
    └── items/                # 道具
```

### 2.2 旧结构 → 新结构映射

| 旧结构 | 新结构 | 动作 |
|---|---|---|
| `正文/` | `chapters/` | 重命名 |
| `人物/` | `entities/characters/` | 重命名+嵌套 |
| `设定/` | `entities/settings/` | 重命名+嵌套 |
| `地点/` | `entities/locations/` | 重命名+嵌套 |
| `道具/` | `entities/items/` | 重命名+嵌套 |
| `大纲.md` | `outline.md` | 合并 |
| `框架.md` | `framework.md` | 重命名 |
| `开篇.md` | `chapters/第001章-*.md` | 移入正文 |

### 2.3 迁移规则

1. **新建项目**：必须使用新结构（chapters/ + entities/）
2. **旧项目**：逐步迁移到新结构
3. **混合状态**：允许新旧并存，但新建内容必须进新结构

## 三、职责划分（三层架构）

### 3.1 methods/ — 方法论层
- **定位**：原创的可复用写作方法论
- **内容**：
  - 写作技巧（结构学、人物学、节奏学等）
  - 可执行 SOP（网文写作最强SOP、改稿润色指令库等）
  - 模板库（作战卡、启动包、体检表等）
  - 项目骨架模板
- **特征**：原创、系统化、可复用

### 3.2 knowledge/ — 知识实体层
- **定位**：结构化知识库，AI 可读
- **内容**：
  - `craft/` — 写作技艺知识
  - `genres/` — 题材分类知识
  - `platforms/` — 平台规则知识
  - `中国网文/` — 行业分析知识
- **特征**：结构化、分类化、知识图谱

### 3.3 ai/ — AI 协作层
- **定位**：AI 专用资源和约束
- **内容**：
  - `prompts/` — AI 提示词模板
  - `workflows/` — AI 工作流定义
  - `constraints/` — AI 约束文件
  - `validation/` — AI 输出校验规则
  - `search/` — AI 检索索引
  - `skills/` — AI 技能定义
  - `agents/` — AI 代理定义
  - `maintenance/` — AI 维护工作流
- **特征**：AI 专用、机器可读、自动化

### 3.4 职责划分规则

| 内容类型 | 归属目录 | 判断标准 |
|---|---|---|
| 原创方法论 | methods/ | 原创、系统化、可复用 |
| 外部参考资料 | references/ | 外部来源、非原创 |
| 结构化知识 | knowledge/ | 分类化、知识图谱 |
| AI 专用资源 | ai/ | 专为 AI 设计 |
| 项目专属内容 | projects/ | 属于特定项目 |
| 草稿/未完成 | drafts/ | 未校验、未完成 |
| 历史归档 | archive/ | 不再迭代 |

## 四、旧文档处理规则

### 4.1 处理策略

| 文档状态 | 处理方式 | 说明 |
|---|---|---|
| **活跃（active）** | 保留并更新 | 当前正在使用的规范 |
| **废弃（deprecated）** | 移动到 archive/ | 已被新规范替代 |
| **重复（duplicate）** | 合并后删除 | 内容重复，保留一份 |
| **过时（outdated）** | 更新或归档 | 内容过时，需更新或归档 |

### 4.2 旧规范处理

| 旧规范 | 新位置 | 状态 | 说明 |
|---|---|---|---|
| 维护标准.md | schema/维护标准.md | active | 已合并 |
| 目录与命名规范.md | schema/目录与命名规范.md | active | 已合并 |
| frontmatter规范.md | schema/frontmatter规范.md | active | 已合并 |
| 项目结构规范.md | schema/项目结构规范.md | active | 已合并 |
| 链接规范.md | schema/链接规范.md | active | 已合并 |
| AI协作规范.md | schema/AI协作规范.md | active | 已合并 |

### 4.3 旧文档清理规则

1. **不允许多套规范同时 active**：全库只能有一套活跃规范
2. **旧规范统一归档**：废弃规范移动到 `archive/规范归档/`
3. **链接更新**：所有指向旧规范的链接必须更新到新位置
4. **版本标记**：旧规范文件头添加 `status: deprecated`

## 六、项目状态管理

### 6.1 状态文件

- **唯一状态文件**：`projects/作品名/STATUS.md`
- **内容**：进度数字、阶段标记、章节推进表、下一步+卡点
- **更新频率**：每次写完一章或推进一个阶段时更新

### 6.2 状态字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `阶段` | string | 构思/大纲/开篇/连载/完结 |
| `进度` | string | 百分比或具体数字 |
| `当前在写` | string | 当前正在写的章节 |
| `下一步` | string | 下一步计划 |
| `卡点` | string | 当前遇到的问题 |

## 八、维护机制

### 8.1 规范变更流程

1. **提案**：提出规范变更建议
2. **讨论**：团队讨论，达成共识
3. **更新**：更新本文件和对应规范文件
4. **执行**：执行迁移/清理/更新
5. **验证**：跑校验脚本，确保 ERROR=0

### 8.2 定期审查

- **频率**：每季度一次
- **内容**：
  - 检查规范一致性
  - 清理废弃文档
  - 更新过时内容
  - 验证目录结构

### 8.3 门禁机制

- **pre-commit 钩子**：提交前自动机检
- **校验脚本**：`tools/scripts/validation/校验脚本.py`
- **ERROR=0**：才能提交
