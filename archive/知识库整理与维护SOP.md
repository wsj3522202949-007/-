# 知识库整理与维护 SOP

> 本文按现有结构量身定制，目标是让这个知识库从“已经能用”变成“长期可维护、可检索、可迁移”。

## 一、先定三条铁律

1. **统一编码：全部使用 UTF-8 without BOM**，避免 Obsidian 显示正常、脚本/Git/PowerShell 读取乱码。
2. **统一 frontmatter**：至少保留 `type`、`area`、`status`，工具库可追加 `platform`、`use_case`、`license`。
3. **统一命名**：中文目录与文件名可用中文，但避免空格、全角括号混用、随意缩写。

## 二、顶层目录职责

| 目录 | 用途 | 放入内容 | 禁止放入 |
|---|---|---|---|
| `收件箱` | 临时收集 | 刚下载资料、待读链接、随手摘录 | 已整理完成的长期内容 |
| `日记` | 时间流 | 每日笔记、复盘、写作进度日志 | 需要跨项目长期引用的知识 |
| `模板` | 可复用模板 | 每日笔记模板、读书笔记模板、项目初始化模板 | 单个项目独有的正文 |
| `索引` | 导航入口 | 知识地图、MOC、常用入口 | 原始素材和正文 |
| `资料` | 参考资料 | 读书笔记、外部资料摘要、方法论文档 | 只属于某个项目的正文 |
| `项目` | 非小说项目 | 通用项目、合作项目、实验项目 | 长期小说作品正文；若项目不多，也可考虑并入 `小说/projects` |
| `小说` | 小说主系统 | 方法论、工具库、archive、projects、维护脚本 | 与小说无关的其他领域资料 |

## 三、小说区标准结构

建议固定为：

```
小说/
├── README.md                 # 唯一入口，只做三件事：这是什么、怎么用、去哪找
├── methods/         # 方法论总集，不要继续膨胀成多个“最强xxx”
├── 库/                       # 外部工具、资料库、分类导航
├── projects/                 # 当前活跃项目
├── archive/                  # 旧稿、原始素材、不再迭代的内容
├── 维护/                     # 校验脚本、维护日志、修复脚本
└── 仪表盘.md                 # 可保留，但不要让它替代 README
```

如果已经有 `小说/维护` 和 `小说/maintenance`，建议只保留一个，优先用 `维护`。

## 四、frontmatter 规范

### 4.1 通用笔记模板

```yaml
---
type: daily-note
area: 写作
status: active
tags: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

### 4.2 读书笔记模板

```yaml
---
type: book-note
area: 资料
status: active
tags: []
source: 《书名》
author: 作者
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

### 4.3 项目 README 模板

```yaml
---
type: project
area: 小说
status: wip
tags: []
genre: 都市/重生
platform: 番茄
pov: 男主
chapters_planned: 30
chapters_written: 0

```

```yaml

```

```yaml

```

## 五、命名规范

### 5.1 目录命名

- 优先用中文名词，不要用动词。
- 推荐：`正文`、`设定`、`人物`、`地点`、`道具`、`大纲`。
- 不推荐：`写正文`、`搞设定`、`待整理`。

### 5.2 文件命名

- 章节统一为：`第001章-章节标题.md`
- 项目统一为：`projects/作品名/`
- 知识页统一为：`人物/林傲.md`，不要 `人物/林傲最终版.md`
- 不要混用 `维护` 与 `maintenance`，不要混用 `库` 与 `archive`

### 5.3 项目内部结构

每个活跃项目至少包含：

```
projects/作品名/
├── README.md
├── STATUS.md
├── TODO.md
├── 框架.md 或 大纲.md
├── 分卷细纲.md
├── 风格校准文档.md
├── 人物/
├── 地点/
├── 设定/
├── 道具/
└── 正文/
```

## 六、内容整理流程

### 6.1 新内容入库流程

1. 先放进 `收件箱`。
2. 判断属于“日常记录”“项目内容”“参考资料”“方法论”。
3. 放入对应目录，并补 frontmatter。
4. 如果是参考资料，同步决定是否放入 `小说/库` 或 `资料`。
5. 更新 `索引/知识地图.md` 的对应入口。

### 6.2 项目迁移流程

1. 从 `收件箱` 或散落位置把内容归到对应 `projects/作品名/`。
2. 拆成 `人物/`、`地点/`、`设定/`、`道具/`、`正文/`。
3. 正文统一改成 `第001章-...` 命名。
4. 补章节 frontmatter 与 `写作进度.md`。
5. 运行 `tools/scripts/validation/校验脚本.py` 做基础检查。

### 6.3 归档流程

1. 不再活跃的内容迁到 `archive`。
2. 保留原始链接、来源说明。
3. 从活跃入口中移除，但保留归档入口。
4. 如果资源库中有明显低价值条目，可优先整理成“精选清单”，而不是继续堆积。

## 七、小说方法论文档瘦身建议

目前建议保留 3 个主入口：

- **总纲入口**：`methods/INDEX.md` 或 `导览.md`
- **执行入口**：`methods/QUICK_START.md`
- **吸收地图**：`methods/最强知识蒸馏总集_吸收地图.md`

其余文档尽量降级为：
- `改稿润色指令库.md`
- `网文写作最强SOP.md`
- `最强去AI味铁律.md`
- `模板库.md`

也就是说：让“主文档做索引，子文档做能力拆解”，而不是让五个主文档互相竞争。

## 八、索引与知识地图更新规则

- `索引/知识地图.md` 至少维护三块：核心主题、活跃项目、常用工具/资料入口。
- 每次新增一个活跃项目，都要更新项目表。
- 每次新增一个重要方法论文档，都要更新“当前推荐阅读”区。
- 如果某条链接失效，优先修复；无法修复则归档并标注废弃原因。

## 九、维护节奏

| 频率 | 动作 |
|---|---|
| 每日 | 写 `日记/YYYY-MM-DD.md`，收件箱清零 |
| 每周 | 跑一次 `tools/scripts/validation/校验脚本.py`，修正 frontmatter 与链接 |
| 每月 | 更新 `索引/知识地图.md`，归档旧稿，瘦身方法论文档 |
| 每季度 | 检查 `小说/库` 和 `资料`，删除低价值重复项 |

## 十、常见错误与标准处理

| 错误 | 标准处理 |
|---|---|
| frontmatter 缺失 | 直接补，不改正文 |
| 标签混用 `area/` 与 `tags` | 统一 `area` 放领域，`tags` 放能力/场景 |
| 章节命名不规范 | 批量重命名为 `第NNN章-...` |
| 知识页散落在根目录 | 迁移到 `projects/作品名/人物|地点|设定|道具/` |
| 工具库重复入库 | 保留一份主索引，避免重复收藏 |
| 链接失效 | 修复优先，无法修复则归档并标注原因 |
| 乱码文件 | 统一转成 UTF-8 without BOM |

## 十一、从空到可用的最小启动清单

如果你现在想立刻按这个 SOP 整理，按这个顺序做最快：

1. 统一所有 `.md` 为 UTF-8 without BOM。
2. 把 `README.md` 整理成真正的总入口。
3. 把 `索引/知识地图.md` 从占位模板改成真实导航。
4. 明确 `收件箱`、`日记`、`项目` 的用途，至少写一个启动说明。
5. 把 `小说/通用小说创作流程` 收敛成“总纲 + 执行入口 + 子能力文档”三层。
6. 跑一次 `tools/scripts/validation/校验脚本.py`，先修 ERROR，再修 WARN。
